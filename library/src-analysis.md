# hana — `src/` codebase analysis

> Conceptual explanations (sub-system cores / modules / module extensors) for every directory
> directly under `src/`, produced by one research agent per code segment. Batch #1 = `core/` + `main.zig`.
>
> Legend:
> - **Sub-system core** — eponymous pillar file(s) of a directory + directly supporting files + the
>   core contracts/surfaces they offer. "Hard core" = essential for hana to keep working; "soft core" =
>   the essential pillar of a sub-system that hana itself doesn't require at runtime.
> - **Module** — a direct contract consumer that extends a core sub-system but isn't required to keep
>   that sub-system running.
> - **Module extensor** — directly extends a module; not required for that module to function.
>
> **2026-09-26 reorg note.** `src/core/` was reorganized (commits `b33f81b`/`8f78f7a` "automated sync"):
> the flat core plus `src/model/` is now split into `architecture/{contract,model}.zig`,
> `loop/{events,pipeline}.zig`, `proc/{lifecycle,persist,restart,signals,spawn}.zig`,
> `display/{scale,usable_area}.zig`, a pure **shelf** (`bounded, constants, cycle, idmap, ids, log,
> paths, scaling, time`), and `x11/{atoms,ledger,masks,reconcile,requests,sink,xcb}.zig`. `utils.zig`,
> `runtime/`, `sync.zig`, `wire.zig`, `screen.zig`, and `geometry/` are gone; every symbol has a named
> home (see ARCHITECTURE.md). Sections 1-8 below are re-verified against the new layout; the parenthesized
> old names are for continuity.

# 1. `src/main.zig` — composition root (HARD core)

**Summary.** `src/main.zig` is the single entry point that wires every subsystem together: it opens the X11 connection, claims WM ownership, loads config, initializes core/window/pipeline/restart/signals in dependency order, hands the heap-allocated config to `core.State`, seeds the tiling params and optional bar surface, optionally adopts a persisted session across a re-exec, and finally hands control to the event loop (`events.run`). It is the only module that names the hard subsystems directly; optional subsystems (bar, tiling) are reached only through build-generated registries and `build_options` gates.

**Boot sequence (high-level).**
1. **Connect & claim the WM grab** — `connectToX` (`src/main.zig:164`) opens the XCB connection, grabs the root screen, and claims `SubstructureRedirectMask` with a *checked* request (`src/main.zig:178`); `xcb_request_check` fails loudly with `error.AnotherWMRunning` if another WM holds the grab. Disconnect is deferred but guarded: never tear down a stream the server already dropped.
2. **Atoms before DPI** — `atoms.initAtomCache` (`src/main.zig:51`, was `utils.initAtomCache`) interns the atom cache *first* because `scale.detectDpi` resolves `RESOURCE_MANAGER` through that cache (`src/main.zig:53`); without it `Xft.dpi` would never be read. DPI lands in `core.dpi_info`.
3. **Input init** — `input.setup` + `input.initXkb` (`src/main.zig:55`) arm XKB before any key parsing.
4. **Config load → heap box → core.init** — `config.load` reads files; the value is copied into an `alloc.create(types.Config)` box so `core.State.config` holds a *pointer* that reload swaps atomically. `core.init` takes ownership and must run before any `core.getState()`.
5. **Keybind build ordering** — `input.buildKeybinds(...)` runs only once both the live config and XKB exist, because its map entries **borrow** `Action`s out of the live config.
6. **restart.init** resolves `/proc/self/exe` *before* any reload/reexec request can arrive.
7. **Defer/LIFO + identity guard** — the config-deinit defer (`src/main.zig:87-91`) checks `core.getState().config == initial_config`: after a reload, `events.handleConfigReload` already deinits/destroys the displaced boot box, so the guard turns a shutdown double-free into a no-op. `input.deinitKeybinds` is registered *after* so LIFO releases the resolver map before the borrowed keybindings die.
8. **WM chores** — `requests.advertiseEwmhSupport` (was `utils.advertiseEwmhSupport`), `signals.setup`, `events.grabKeybindings`, then `window.init` (uniform `window_modules` lifecycle dispatch).
9. **Model pipeline before seeding** — `pipeline.init()` owns the model; then `actions.seedParamsFromConfig()` (`src/main.zig:111`) stamps every workspace's kind/variant/master-count from config. No reconcile yet — nothing is managed, so there is no X state to push.
10. **Optional surface** — bar lifecycle through `surfaces.init()/deinit()` gated on `build_options.has_bar`, *before* the restore path so the bar-aware workarea is live.
11. **Restore hand-off** — if `HANA_RESTORE` is set (set by `restart.execNext`), `adoptRestoredSession` (`src/main.zig:136`) loads the JSON, adopts root children, `actions.applyRestoredLevel()`, then runs one focus reconcile.
12. **Event loop** — `events.run()` polls X fd + signal fd, drains signal bytes before flags, consumes reload before re-exec, folds bar timers through `surfaces.pollTimeoutMs()`.

**Implementation highlights.**
- `std_options` (`src/main.zig:34-37`): arms Zig's segfault handler even though hana builds `ReleaseFast` (DWARF stripped, safety off) — otherwise an uncaught SIGSEGV would abort with zero trace. Fault address lands in `~/hana-crash.log`.
- `adoptRestoredSession` (`src/main.zig:136-156`): `persist.loadToGlobal` (version-checked against `persist_version = 5`), then `window.adoptRootWindows()` (batched cookies fired up-front), then `actions.applyRestoredLevel()` + one reconcile; focus restore routes through the same `focus.prepareFocus(focused, .window_spawn)` + `pipeline.reconcileGrabFocus` entry the mapRequest path uses.
- `connectToX` (`src/main.zig:164-194`): single-sourced connection; errors surfaced as `error.X11ConnectionFailed` / `X11ScreenFailed` / `AnotherWMRunning`. `XSession` bundles `core.Connection/Screen/WindowId`.

**Edges & contracts.** Names directly (hard core): `core`, `config`, `scale`, `input`, `restart`, `persist`, `window`, `actions`, `pipeline`, `focus`, `signals`, `events`, `atoms`, `requests`, `masks`, `log`. Deliberately NOT named: the **bar** — reached only as `surfaces.Surfaces` under a `build_options.has_bar` runtime branch; **tiling** — never touched even by name; layout seeding resolves through the config/`tiling_seam` registry. Ownership contracts: `core.init` takes ownership of the config pointer; the model is created by `pipeline.init`, exposed read-only via `pipeline.model()`. `HANA_RESTORE` is the only information funneled from the dying to the fresh process.

# 2. `src/core/` hub — `core.zig` + `loop/events.zig` + `loop/pipeline.zig` (HARD core)
*(paths post-reorg; the event loop and reconcile pipeline are now in `src/core/loop/`)*

**Summary.** Core is the process hub: `core.State` is the single heap of global live facts (connection, screen, root, allocator, atomically-swapped config pointer), the event loop in `events.zig` is the sole driver, and `pipeline.zig` is the reconcile choke point that funnels every model→wire mutation through one sync boundary under an X server grab. Everything reaches optional subsystems only through build-generated contracts (`surfaces`, registries), so core names no non-core module.

**How it works (high-level).**
- **Event loop shape: block-with-deadline poll.** `events.run()` (events.zig:597) polls exactly two fds — the XCB socket and the signal self-pipe — with `poll_timeout_ms` defaulting to `-1` (block forever). The only timer sources are bar-owned: `surfaces.pollTimeoutMs()` contributes a non-negative deadline, and a timeout wake is forwarded verbatim to `surfaces.onPollWakeup()` + `surfaces.updateClock()`.
- **Routing.** Signals drain first via `signals.drainAndDispatch` (events.zig:637), consuming flags **before** the ready split so a flag-only request can't stall on unrelated traffic. Reload is consumed before re-exec so a chained bind applies+snapshots config before the successor boots. X events dispatch through a comptime O(1) `dispatch_table` (events.zig:115), with motion-run coalescing (`collapseMotionRun`, events.zig:483) under a per-batch budget of `max_events_per_batch`=128 / `max_queued_drain`=256.
- **Reconcile triggering.** The model is not diffed on every event; actions bump fact revisions (`core.focus/window/fullscreen/layout.bump()`) and then push one reconcile entry point through the pipeline. Inside `reconcile.reconcile` (`x11/reconcile.zig`) the reconcile/ledger pair computes desired state unconditionally but delta-sends against the write-only sent ledger (`x11/ledger.zig`), eliding idempotent resends — a client that mutated its own geometry is repaired on the next reconcile (drift-proof, no diff cache).
- **Sync gate / stepping policy.** Wire sends are serialized by an X server grab: `withServerGrab` (loop/pipeline.zig:179) brackets grab → body → `ungrabAndFlush`. No flush happens inside reconcile ("DO NOT FLUSH HERE", x11/reconcile.zig); the caller owns flushing.

**Implementation highlights.**
- `core.State` (core.zig:50): one optional bundling `conn/screen/root/alloc/config` + `facts` so access before `init()` panics (`getState`, core.zig:124) instead of reading undefined memory; `config` is a heap pointer swapped atomically on reload.
- `core.Facts` + comptime accessors (core.zig:65): `factAccessors` generates `rev()`/`bump()` pairs, exposed as `core.focus/window/fullscreen/layout` (core.zig:91-94). Consumers diff `rev()` to detect redraws (bar `DirtySources`; events snapshots facts per batch to skip the border sweep when nothing border-relevant changed).
- Reconcile entry points (pipeline.zig:205-328): `reconcileGrabFocus`, `reconcileUnderGrabNow`, `reconcileUnderGrabNowFullscreen`, `focusOnlyCommit`, `reconcileNow`, `dragTick`, `grabCtx`.
- Model gate: `model()` returns `*const model.Model` (compile-error mutation tripwire, pipeline.zig:44); a mutable handle needs `pipeline.Gate` (`mut()`, pipeline.zig:58), held only by transition layers.
- `preReconcileDuties` (pipeline.zig:158): the single choke point applying the active layout's pure `preReconcile` delta (scroll snap/clamp) to model params — layouts never get a mutable model pointer.
- Event decode/dispatch machinery: `asHandler` (events.zig:64) comptime type-checks each handler; `dispatch` (events.zig:162) warns on X-error pseudo-events, routes RandR events first, bounds-guards the table, strips the synthetic-send_event bit.
- Config reload (`handleConfigReload`, events.zig:289): live load, heap-boxed pointer swap, `detectChanges`-gated subsystem reloads, displaced config deinit last — ordering is load-bearing.
- Re-exec (`handleReexec`, events.zig:396): pins the config snapshot, persists first (a failed save aborts the hand-off), then `xcb_disconnect` + `restart.execNext`.

**Edges & contracts.** model = owned read-only (`*const`); only gate-holding layers mutate. window/actions own model transitions, call pipeline entries after bumping facts. input routed via `dispatch_table`; `XK` enum (core.zig:14) is the shared translation vocabulary. config = `*types.Config` in `core.State`, reload is core-owned. bar surface = wholly through comptime-null `surfaces.Surfaces`; every call site compiles away when `has_bar` is false. Wire sends are strictly under one server grab; the event loop owns the sole flush points.

# 3. `src/core/architecture/contract.zig` — the open contracts (HARD core)
*(moved out of `pure/` into `architecture/` 2026-09-26)*

**Summary.** The contract is the single file defining the **open interface types** optional subsystems bind to: `Surfaces` (what the bar satisfies), `WindowModule` (window-owner addons), `Segment`/`BarOverlay`/`DirtySources` (bar segments), and `Layout` plus the tiling interchange vocabulary (`View`/`List`/`Placement`/`HintsView`/`Env`). It exists so core can dispatch into any compiled-in module through uniform loops without ever naming an optional subsystem. Registries are *mostly* passed in as dispatch-loop parameters, and bar-only types cross the boundary as `*anyopaque`; the one exception is the generated `tiling_modules` registry, which the file imports and re-exports as `contract.tiling_mods` and which is now documented at BOTH sites as the file's single deliberate generated-module edge. Its own doc comment used to claim the file had no such edge at all (the §3 item 12 defect); the claim was wrong, not the import, and the comment has been corrected in place. Registration lives in build-GENERATED modules produced by `build.zig`.

**How it works (high-level).**
- **Binding**: every module file declares `pub const module: contract.<T>`; build.zig collects every `modules/` dir into an owner registry and emits `pub const modules = [_]contract.{T}{ ... }`. Struct-initializer field defaults (`= null`, empty `name`) are the absence mechanism — an unbound hook stays `null`.
- **Null-hook compile-away**: hooks are optional `?*const fn`; a dispatch on `null` is dead at comptime. Absent subsystems vanish via `build_options` (`tiling_mods` is `&[_]Layout{}` when `!has_tiling`, contract.zig:48-49; `has_bar` guards compile call sites out).
- **Priority**: *multi-binder* hooks (init/deinit, `notifyConfigureIfPending`, `onWindowGone`, serialize/deserialize, `setEwmhFullscreenState`, `armPendingBarHide/Show`) fan out over the registry. *Single-binder* hooks are enumerated in `single_binder_hooks` (contract.zig:260-270) and dispatch first-match (`providerOf`/`callFirst`/`callFirstBool`); the generated registry comptime-asserts ≤1 binder per listed hook and name-uniqueness for `Segment`/`Layout`. Priority order = registry order = deterministic sorted-stem filesystem scan.
- **Two-level blob adoption** (window persistence): `serializeWindow` (contract.zig:154) returns a per-window blob or null; each module decides from model state whether it owns the blob (at most one per window). The persist layer stamps each blob `[ext_format_version][ordinal][payload]`. Adoption fast-paths on the ordinal; a magic-byte scan falls back when the ordinal no longer resolves (module removed between runs). `deserializeWindow` may write state, so it dispatches only under the gate-holding restore path.

**Implementation highlights.**
- `Surfaces` (contract.zig:79-128): fn-pointer struct; boot (init/deinit/onReload/refreshConfig), event-loop (handleExpose/updateIfDirty/pollTimeoutMs/onPollWakeup/updateClock), RandR (randrFirstEvent/handleRandrEvent/runPendingRedetect), input routing, visibility/fullscreen hooks.
- `WindowModule` (contract.zig:135-250): flat all-optional-hook struct — lifecycle, persistence seam, hide/restore family, screen-covering family, workspaces family, floating family incl. drag/resize.
- `Segment` (contract.zig:389-481): `name`, role capabilities `self_ticking`/`center_slot`, repaint contract via `dirty_sources` + `needsRepaint`, lifecycle with bar-provided `*const anyopaque` handlers, metrics/draw/click/scroll/drag hooks, chrome-overlay extras, `onBarShown`, runtime `overlay`.
- `Layout` (contract.zig:496-526): `name`, `compute(*const View, *List)` (exactly one placement per window), variants + `variant_parse`, scroll hooks `slotWidth`/`maxOffset`/`preReconcile` (pure, params by value), bar metadata `icon`/`indicators`.
- Interchange vocabulary (contract.zig:535-584): `View`, `Placement`, `List = utils.BoundedList(Placement, model.store_capacity)` (:557), `parked_rect` sentinel (:547), `HintsView` with `forWin` scan (:568), caller-resolved `Env`. Lives on the contract so the always-compiled reconciler can name them with zero tiling modules present.
- Dispatch primitives (contract.zig:285-341): `providerOf` (first binder), `callFirst`/`callFirstBool` (first-match call), `callAll` (fan-out), `callFirstTrue` (short-circuit).

**Edges & contracts.** Contract imports `core`/`xcb` and the generated `tiling_modules` registry (re-exported at :48-49) — its header's "no-import discipline" claim is false; otherwise no feature module is named. Bar-side structs cross as `*anyopaque`; dispatch helpers take the registry as a parameter. The contract binds `build_options` flags; `moduleOf(kind)` is the single bounds-checked registry lookup; `activeLayoutKind(kind)` applies the tiling gates purely. Model handedness: read-only `*const` on serialization, mutable on adoption.

# 4. `src/core/proc/` session & lifecycle — `persist.zig` + `restart.zig` + `signals.zig` + `spawn.zig` (HARD core)
*(the old `runtime/` dir is gone; these four moved to `proc/` 2026-09-26)*

**Summary.** These four files own hana's process hand-off and session durability. `restart.zig` is the re-exec coordinator, `persist.zig` snapshots the model plus per-window feature blobs to a JSON file, `signals.zig` routes POSIX signals through a self-pipe with a loss-proof pending bitmap and an alternate-stack backtrace dump, and `spawn.zig` forks detached commands as a session leader, with the WM acting as child subreaper and an out-of-band failure pipe. Together they make the entire binary hot-reloadable while keeping the event loop single-threaded and the signal path async-signal-safe.

**How it works (high-level).**
- **Reload vs re-exec**: config reload is in-place (swap config, reseed params, rebuild keybinds); re-exec replaces the whole image (pin config snapshot, persist, disconnect, `execv` self). The run loop consumes reload *before* re-exec so a chained `["reload_config","reload_hana"]` boots from the refreshed snapshot; a failed save aborts the hand-off.
- **Persist/adopt round-trip**: save → snapshot (flat `WindowRecord`s) → JSON file → temp-file+rename. Boot does `loadToGlobal` → `adoptRootWindows` (root children adopted directly, since hana never reparents) → `applyRestoredLevel` → one reconcile → focus restore.
- **Signal safety**: handlers do only an atomic `fetchOr` into a `u64` bitmap plus a self-pipe wake byte with full-pipe drain; state never rides on the byte, so quit/reload requests can't be lost in a burst. Dispatching happens on the event loop (`drainAndDispatch`), not in handler context.
- **Spawn model**: single `fork` + `setsid`, with the WM installed as a child subreaper (`PR_SET_CHILD_SUBREAPER`) so orphans re-parent to hana rather than to init. The spawned PID comes from `fork()` itself, so the pipe carries only the failure tag: a clean EOF (the O_CLOEXEC copy closed on a successful exec) means success, one `tag_failed` byte means the exec never happened.

**Implementation highlights.**
- persist.zig: `ext_format_version=2` (name-stamped blob header, `extHeaderLen`/`extPayload`/`extClaimantName`, with v1 ordinal blobs still read); blob stamping in the module loop
- restart.zig: `init` (:60) one-shot `readlinkat("/proc/self/exe")`, full-buffer → unresolvable; `requestReexec`/`consumeReexec` (:80,88) atomic swap; `execNext` (:118) = `setenv("HANA_RESTORE")` + `execv` of the absolute self path (no PATH lookup); must run only after the X connection is closed or the successor's SubstructureRedirect grab gets BadAccess.
- signals.zig: `setup` (:183) self-pipe + HUP/TERM/INT/CHLD/USR1 handlers, `SIGPIPE → SIG_IGN`; `sigaltstack` before arming the ONSTACK handler; `handleBacktraceRequest` (:87) SIGUSR2 dumps the interrupted main thread's frames to `~/hana-crash.log` (raw `write(2)` only, bounded frame-pointer walk, depth ≤96); `dispatchSignal` (:245) SIGCHLD → `spawn.reapPendingChildren` + `drainPendingSpawns`.
- spawn.zig: `executeShellCommand` (:137) workspace snapshot up-front (correct for `[exec, switch_workspace]`), 256-byte stack NUL-termination with heap fallback, hard `max_pending_spawns=16` reject-before-fork; double-fork ladder `forkIntermediate` (:62) / `execAsGrandchild` (:53) with `setsid` + `execvp("/bin/sh","-c",…)`; `finishSpawn` (:241) resolves both pipe ends (both writes under PIPE_BUF); `execSynchronous` (:297) is the opt-in single-fork that blocks on `waitpid`.

**Edges & contracts.** persist iterates `window_modules` in deterministic order, first non-null `serializeWindow` claims the blob; adoption fast-paths on the stamped ordinal, falls back to magic-byte `deserializeWindow`; deserialize dispatches only under `pipeline.mut(&gate)`. The loop drains signals → reload → re-exec. Restore crosses the exec in `HANA_RESTORE`. A failed `persist.save` aborts re-exec and keeps the live connection.

# 5. `src/core/x11/` — synchronization boundary & raw X11 wire (HARD core)
*(re-verified post-reorg; `sync.zig` → `reconcile.zig`, `wire.zig` → `requests.zig` + new `atoms.zig`, `sync_test.zig` → `reconcile_test.zig`)*

**Summary.** `x11/reconcile.zig` is the single reconcile choke point: it rederives the desired state of every stored window each reconcile ("unconditional compute"), diffs that desire against the write-only sent ledger (`x11/ledger.zig`), and emits only the idempotent requests that changed — all batched into one X server grab, released/flushed in one `ungrabAndFlush`. Dispatch goes through the `Sink` interface (`x11/sink.zig:40-56`, defined beside its shims), whose `XcbSink` is the sanctioned seam that touches the wire. The raw libxcb surface is wrapped in `x11/requests.zig` (primitives + EWMH) and `x11/atoms.zig` (comptime atom cache), pinned to a single `@cImport` hub (`x11/xcb.zig`); masks are enumerated in `x11/masks.zig`. The seam is a strict four-layer DAG — reconcile (planning) → ledger (records) → sink (dispatch) → requests/atoms (primitives) — enforced by `check-layers.sh` allowlisting exactly `requests.zig`/`atoms.zig` for raw `xcb_*`. Layer rules: wire-mutating requests and grabs live behind the seam (with an allowlist for requests/atoms and the bar's claim sites), and `model`/`tiling`/`config` stay xcb-free.

**How it works (high-level).**
- **Reconcile-then-step.** `reconcile.reconcile(m, ctx, opts)` walks the model store in one fused loop; per window it computes a `Desire{rect,bw,pixel,parked}` (reconcile.zig), diffs against the ledger, emits only changed requests. Parked windows emit `park` only on the transition (reconcile.zig:390). Compute is unconditional ⇒ any client-mutated geometry is repaired next reconcile — drift-proof with no diff cache.
- **Serialization via the grab.** The reconcile bracket (reconcile.zig:98-108) = `grabServer() -> reconcile() -> ungrabAndFlush()` with release in a `defer`. A *parallel* implementation lives in `loop/pipeline.withServerGrab` (loop/pipeline.zig:179) — hana keeps two (src-improvements.md §5 item 4). `reconcile()` never flushes; the caller is the grab bracket or the event loop's batch-end flush.
- **Batching.** No per-request flush → every `Sink` call just queues bytes; one flush at grab release delivers the whole reconcile. `geomBordered` folds border width into a single configure; `park` merges offscreen-X + BELOW into one configure_window; the one blocking call is the fullscreen EWMH `_NET_WM_STATE` list-merge — a `xcb_get_property` round-trip *inside* the grab (sink.zig:193-194), the only place the "zero round trips in the grab" invariant (reconcile.zig:99-100) is broken.
- **The xcb wrapper & masks.** `xcb.zig` is the single header translation hub (xcb.h, xcbext, randr, xkb). `requests.zig` is the allowlisted primitive home (`configureWindow`, `raiseWindow`, `setBorderPixel`, `grabServer`/`ungrabAndFlush`, `changeProperty`, EWMH advertisement) and `atoms.zig` the comptime atom cache — together the only modules with raw `xcb_*` access. `masks.zig` separates cheaply-reproducible mask constants from the model layer.

**Implementation highlights.**
- `Sink` interface — 11-slot `VTable` (map, geom, geom_bordered, border_width, border_pixel, park, stack_only, set_ewmh_fullscreen, flush, grab_server, ungrab_and_flush) defined in `x11/sink.zig:40-56` beside its shims (a genuine post-reorg structural win; the old low-level-imports-high-level inversion is gone). Tests wire the `TestSink` recorder (src/test/helpers.zig).
- Ledger — `x11/ledger.zig`: `SentEntry` (ledger.zig:27-33) with explicit `has_rect` flag; kept in a process-global `State` second store (`ledger.zig:42-48`, binary-search `sentGetOrPut` :60-63) parallel to the model, not on the model entry; `forget` drops records on unmanage (X ids recycle).
- Drop-in fast path — `reconcileDragTick` (reconcile.zig): sinks a single geometry for the dragged floating window, carries last real `bw`/`pixel` across the ledger to avoid a border flash.
- `placementOfSlot` (reconcile.zig): O(1) slot→placement table replacing an O(N) scan.
- Tiling interchange — reconcile builds `contract.View` and a zero-alloc `contract.List` of `Placement`s; `contract.parked_rect` is the sentinel; no-tiling builds gate the block (and the `tiling_mods` re-export contract.zig:48-49) behind `has_tiling`.
- Masks — `EventMasks.root_window`/`managed_window` (masks.zig) carry DWM-derived masks with three documented deviations; `synthetic_event_mask` (masks.zig:59) strips the SendEvent bit (aliases any code ≥ 0x80 onto a core code — see src-improvements.md §2 item 3).
- Wire helpers — comptime field-driven `AtomCache` interned in one batch (`x11/atoms.zig`); `supported_atoms ⊂ AtomCache` enforced at comptime; `collectPropertyReply` is poll-first then blocking. Both sit in `requests.zig`/`atoms.zig`.

**Edges & contracts.** loop/pipeline owns the global Model + shared `XcbSink`, builds the per-reconcile ctx (`g_ctx`, loop/pipeline.zig:122-141); layout `preReconcile` duties run before any reconcile and reconcile never mutates model params. The event loop never calls the sink for mutations, only flushes. window.zig touches the ledger reads/writes only. `model/`, `tiling/`, `config/` are body-scanned for any `xcb` token; only `core/x11/` (requests, atoms, sink, xcb) + the bar's allowlisted claim sites may issue wire-mutating calls.

# 6. `src/core/display/` scaling & screen — `scale.zig` + `usable_area.zig` (HARD core)
*(`screen.zig` → `usable_area.zig`; both moved into `display/` 2026-09-26; the value→pixel formulas now live in the shelf as `pure/scaling.zig`)*

**Summary.** `display/scale.zig` performs one-time DPI detection at boot (`Xft.dpi` from the X RESOURCE_MANAGER property → physical-geometry math → a 96.0 baseline), caches it in `core.dpi_info`, and exposes pure pixel-conversion helpers for font and bar sizing. `display/usable_area.zig` is a comptime-fixed "claim" ledger: the bar pushes how many pixels it takes off which edge, and core computes `workArea()` — the usable desktop rect — by subtracting active claims, so hiding the bar or entering fullscreen releases space back to window placement.

**How it works (high-level).**
- **DPI detection.** `main.zig:51-53` interns the atom cache then calls `scale.detectDpi`, storing the result in `core.dpi_info`. Detection prefers `Xft.dpi` (`readXftDpi` fetches RESOURCE_MANAGER; `parseXftDpi` scans for `Xft.dpi:`); any value inside the `[50, 300]` band wins, else `calcDpiFromGeometry` averages X/Y pixels-per-inch from screen mm.
- **Scale application.** DPI is not multiplied into layout numbers (layout uses `ScalableValue` percentages against screen height). `scaleFontSize` resolves relative to a fixed 1080 baseline; `scaleBarHeight` resolves against the real screen. DPI is handed to cairo/Pango at bar draw-context creation; scaled border widths come from `core.borderWidth()`.
- **Screen/workarea.** Surfaces `setClaim(id, edge, px)` (display/usable_area.zig:78); with `has_bar` there is one claim slot. The bar syncs its claim (`syncScreenClaim`, bar.zig:1402) at init/reload/visibility changes. `workArea()` (display/usable_area.zig:89-110, returns `model.Rect`) saturating-subtracts claims. # 8. `src/core/architecture/model.zig` — the model sub-system (HARD core)
*(moved `src/model/` → `src/core/pure/` → now `src/core/architecture/` 2026-09-26; the separate `geometry/geom.zig` was merged in — `Rect`/`Margins` are `model.Rect`/`model.Margins`)*

**Summary.** The `model` module is the xcb-free single source of truth for window-management state (`src/core/architecture/model.zig:1-5`). It defines canonical identity types (`WindowId`, `WSId`), the per-window `Entry` and per-workspace `WsState`, and the global `Model` container, all backed by allocation-free `bounded.Store`/`BoundedList` collections. The model owns no X11 code and is read-mostly: only gated transit layers mutate it via `*Model`; other layers read through `*const Model`. The observable deltas it encodes (focus/MRU, order/mask/presence changes) are what drive repaint/reconcile.

**How it works (high-level).**
- **Window store (per-window state):** `model.Store(WindowId, Entry, store_capacity)` (:126, :136) holds every managed window. `Entry` (:93-106) captures `mask`, `anchor` (tiled vs `floating: Rect`), `size_hints`, cached `home_ws`, `presence` (`present/parked/covering`), and `covering_ws`.
- **Per-workspace state:** `Model.ws` is `[constants.max_workspaces]WsState` (:137); `WsState` (:108-112) has `tiled_order: OrderList`, `focus_mru: MruList`, and `params: LayoutParams` (:64-78).
- **Global state:** `current: WSId` (:138), `focused: ?WindowId` (:139), `all_view_active: bool` (:140).
- **Store layout:** sorted-key `bounded.Store` over `WindowId` with fixed arrays and binary search (`lowerBound`/`exactAt`); membership lists are `BoundedList` — all zero-alloc, fixed capacities.
- **Per-workspace vs per-window:** tags are `Entry.mask` (u64 bit-per-ws via `bit(ws)`/`maskedOn`); tiled placement is a single slot list `ws.tiled_order` (single-membership invariant) with cached `home_ws`. Visibility derives from `presence`, `all_view_active`, and tag tests via `visibleEntry`/`taggedOn`.
- **Mutation access model:** pure queries take `*const Model` (`findHome`, `visibleOn`, `taggedOn`, `isPinned`, `tiledCountOnWs`, `coveringOccupantOnWs`, `fallbackFocusCandidate`); mutators take `*Model` (`register`, `unregister`, `setFocus`, `reorderTiled`, `stepTiled`, `swapPrimary`, `adjustPrimaryWidth`, `applyConfigReload`).
- **Why fact revisions exist:** the model is the source of truth behind the `focus_rev`/`frame_rev` facts (they live in core); any mutation to focus/order/presence/params produces a new observable revision that sync and the bar detect.

**Implementation highlights.**
- Capacities: `store_capacity=128` (:121), `mru_capacity=16` (:122), `max_tiled_per_ws = constants.max_tiled_windows` (:123), `max_layouts=256` (:62).
- Identity: `WindowId`/`WSId` aliased from `pure/ids.zig` so ids cross boundaries unconverted; `ALL_MASK = ~@as(Mask,0)` (:29), `lowestBit` (:130).
- Per-window vocab: `BaseMode = union(enum){ tiled, floating: Rect }` (:80-86), `Presence = enum{present,parked,covering}` (:91), `SizeHints` with `isEmpty()` (:32-54).
- `LayoutParams` (:64-78): `kind` (u8 registry index into the tiling registry), `variant_idx`, `primary_width`, `primary_count`, `secondary_balance`, `viewport_offset`/`viewport_prev_count`.
- `applyConfigReload` (:399-412): copies the template across workspaces but preserves the runtime viewport state.
- `fallbackFocusCandidate` (:300-327): tiered — MRU newest-first, reversed tiled_order, then floating-not-in-tiled_order, skipping excluded/covering.
- `register` (:161-172) with rollback on `CapacityFull`; `unregister` (:174-180) cleans store/home/list/MRU.
- Vocab consumed by the contract: `ConfigureReq`/`HonorDecision` (:250-261), `RestoreOrder = enum{lifo,fifo}` (:248).

**Edges & contracts.** Writes: transit/pipeline layers via the mutation gate. Reads: reconcile extensively (`model.coveringOccupantOnWs` at x11/reconcile.zig:148; the sent ledger = `x11/ledger.zig`, its own `Store(WindowId, SentEntry, store_capacity)`), the bar through contract views. Contract types reference model vocabulary: `View` (order/params/hints), `Placement{win,rect,visible}`, `List = BoundedList(Placement, model.store_capacity)` (:557), `preReconcile` takes `model.LayoutParams` by value. Persistence seams pass the model read-only on serialize and mutable on deserialize. Hiding/covering *records* live in the feature modules; the model carries the state (`presence`, `covering_ws`) and the queries.

# 9. `src/window/` sub-system core — `window.zig` + `icccm.zig` + `borders.zig` (HARD core)

**Summary.** `window.zig` is the window-management pillar: the uniform event-admission core (MapRequest admission + boot-time root adoption) and the single event-handler surface (`handleMapRequest`, `handleConfigureRequest`, `handleEnterNotify`, `handlePropertyNotify`, `handleUnmapNotify`/`handleDestroyNotify`, `handleClientMessage`) that funnels X events into the model through the sync/pipeline gate. `icccm.zig` is the ICCCM/EWMH protocol client — the WM_PROTOCOLS/WM_HINTS focus-property cache and the ICCCM 4.1.7 focus-delivery-model resolution — while `borders.zig` holds the pure geometry/color rules shared by the tiled and floating border sweeps.

**How it works (high-level).**
- **Lifecycle.** `window.init` (:259) resets the single `State`, initializes tracking/focus/wincache, runs every compiled-in `window_modules` module's `init` (uniform fan-out), pre-allocates the spawn queue, and builds the class/float rule maps. `deinit` (:283) reverses in order.
- **Admission.** New mappings enter through `handleMapRequest` (:596): it fires all five property cookies up-front (`fireAdmissionCookies`, :493) so the server processes them in parallel, then drains workspace-resolution replies (`resolveAdmissionDecision`, :436: class rule → PID spawn-queue match → current ws) before `admitWindow` (:665) registers the model entry and seeds the child cache. The same policy (`claimManagedEventMask` :528) is used by the boot-time adoption path (`adoptRootWindows`, :796) for root children surviving a re-exec, re-applying persisted restore records (`applyRestoredRecord`, :709).
- **Event funneling.** Every managed window claims the WM event mask, so all events route through per-window model transitions, then one reconcile under a server grab — with float/crossing-suppression guards (`snapshotSpawnCursor`, `suppressSpawnCrossing`, `crossingShouldDrop`).
- **WindowModule registry.** `window.zig` is the registry owner: `providerOf`/`callHook`/`callHookBool`/`dispatchAll`/`dispatchFirstTrue` wrap the build-generated `window_mods` and the `contract.WindowModule` contract; optional modules (fullscreen/minimize/floating/workspaces) bind hooks without the core naming them.

**Implementation highlights.**
- window.zig: `init`/`deinit` (259/283); `buildRulesMap` (236) class→workspace + float maps (O(1) hash, first-rule-wins); `handleMapRequest` (596) 5-cookie pipeline; `admitWindow` (665); `adoptRootWindows` (796) pipelined attribute+property cookies, restore fast-path on the claimed blob's ordinal; `dispatchAll`/`providerOf` (57/35); child-XID→toplevel `child_cache`.
- icccm.zig: `InputModel` (:32) four ICCCM focus-delivery modes; `firePropQuery`/`queryWMProtocolsProps`/`sendWMTakeFocusKnown`/`supportsWMDeleteCached`; `cache_slots` IdMap (`setCacheArmed`/`peekCachedProps`) + size-hint parsing.
- borders.zig: `borderColorOf` (pure focused/unfocused pixel pick), `isBehindCoveringWindow`, `apply`/`applyWidth` with sync-ledger dedup via `sendBorderColorIfChanged`.

**Edges & contracts.** WindowModule contract: all optional binders, first-match dispatch. Serialization: save stamps the claiming module's ordinal + version; adoption fast-paths on the ordinal and falls back to magic-byte scan across `deserializeWindow` (window.zig:741-756). Ledger reads/writes via `sync.truthRect`/`lastBorderWidthFor`/`markSentBorderWidth` — steady-state sweeps generate zero XCB traffic. Mutable model access only via `pipeline.mut(&gate)`; reconciles via `pipeline.reconcileUnderGrabNow`; `handlePropertyNotify`/`handleClientMessage` are the sync boundary's "allowlisted" non-mutation wire duty.

# 10. `src/window/` actions & focus — `actions.zig` + `focus.zig` (HARD core)

**Summary.** `actions.zig` is the command/verb layer: every config keybind Action and window-lifecycle event funnels into a small set of `pub fn`s, each performing one model transition via the module registry hooks, bumping the relevant core fact, and pushing exactly one pipeline reconcile entry point. `focus.zig` is the focus pillar: it owns the two-phase (prepare-outside-grab / apply-inside-grab) X focus protocol, ICCCM input-model resolution, focus-follows-mouse, focus cycling, EnterNotify suppression, and `_NET_ACTIVE_WINDOW` advertisement. `model.focused` is the single source of truth; `last_applied` is a protocol-side cache.

**How it works (high-level).**
- **Actions → model → pipeline.** Each action enters via `pipeline.mut(&gate)` (pipeline.zig:58), calls a `WindowModule` hook through the registry or a model intrinsic, bumps facts (`core.window/focus/fullscreen.bump()`), and finishes with one reconcile. The shared tail `retile` (actions.zig:96) picks which fact to bump and routes to `reconcileGrabFocus` or `reconcileUnderGrabNow`. Focus is prepared *before* the grab (`prepareAndSetFocus`, actions.zig:179) because input-model resolution is a cache read that must not block inside it.
- **Focus pipeline.** `prepareFocus(win, reason)` (focus.zig:335) resolves the ICCCM input model from the cache, applies a liveness guard, dedups against `last_applied`, derives `CommitFlags`. Ordering: `reconcileGrabFocus(…, order, duty)` applies focus before geometry (`.before`, most actions) or after (`.after`, mapRequest/switchTo — an unmapped target would BadMatch). Commit (`applyPendingFocus`, focus.zig:420) is fire-and-forget XCB: `focusNow`, button-grab handoff, conditional raise, `WM_TAKE_FOCUS`, fact bump, active-window advertisement. `.mouse_enter` is focus-only via `pipeline.focusOnlyCommit` (focus.zig:523).
- **Keybind mapping.** `input.executeAction` (input.zig:329) switches on the Action variant into these fns; mouse bindings target the *clicked* window for `.toggle_floating_window`, the keyboard-focused window otherwise.

**Implementation highlights.**
- actions.zig: `Ctx` withdrawal facts (unmanage captures fullscreen-ws + focus ownership first, actions.zig:69-79); `focusFallback` (:152) → `model.fallbackFocusCandidate`; `retileWithFallback` (:110) bumps the fullscreen fact for covering occupants; `fullscreenToggleWindow` (:265) → `reconcileUnderGrabNowFullscreen` (EWMH + bar unmap inside the same grab); drag/resize seams as uniform dispatch loops (:492-529); tiling verbs (`cycleActiveLayout`, `adjustPrimaryWidthAction`, `swapPrimaryAction`, `moveFocused`); `snapViewportParamsToFocused` (:637); `seedParamsFromConfig` (:759) resolving layout names via `tiling.layoutKindFallingBack`; `applyConfigReload` (:834); `applyRestoredLevel` (:726); `switchTo` (:853) with bar visibility applied X-free; `mapRequest` (:956).
- focus.zig: `Reason` (:203), `CommitFlags` (:234), `FocusTransition` union (:294); `prepareClearFocus` (:390); `advertiseActiveWindow` (:460); `grabButtons` (:177) SYNC-mode regrab for click-to-focus; suppression `shouldSuppressEnterNotify` + `beginTilingOpSettle`/`drainTilingOpSettle` (:534-562); cycling `cycle_buf`/`collectVisibleWindows`/`cycleTarget` (:571-617).

**Edges & contracts.** Actions reach sub-systems only through `contract.WindowModule` via `window.providerOf/callHook/dispatchAll`; `single_binder_hooks` (contract.zig:260) comptime-asserts ≤1 binder. `currentCoveringOccupant` uses the module hook OR vs the core OR-scan contrast. `shouldRaise` (focus.zig:473) never raises hover/spawn/switch reasons — hover raising synthesizes FocusOut/FocusIn pairs that confuse Electron. # 11. `src/window/` tracking & caching — `wincache.zig` + `tracking.zig` (HARD core)

**Summary.** `wincache.zig` is the WM's on-demand read-back cache of per-window geometry-adjacent facts (border color, `WM_NORMAL_HINTS`, owned title string) keyed by window id in a `std.AutoHashMap(u32, WindowData)` singleton hard-bounded at `constants.max_window_cache` (512). `tracking.zig` is a read-through facade over `pipeline.model()`: workspace/current-state queries with zero local storage. Together they answer "what state does window X hold" and "which workspace is current" without redundant reads; geometry proper lives in the model + sync ledger.

**How it works (high-level).**
- wincache entries are created lazily by writers: `cacheSizeHints` stages parsed hints pre-registration; `sendBorderColorIfChanged` (wincache.zig:138) dedups the border-pixel request against the recorded color but *always* records (forced values set outside it, e.g. fullscreen's pixel 0, must land in the cache or the next color change silently skips — the "lost borders" bug). Titles filled by a pipelined cookie pair (`fireTitleCookies` :180 / `collectTitleCookies` :215, `pickTitle` preferring UTF-8); renames hit `refreshTitle` (:222). Reads (`peekTitle`/`peekHints`) are pure hash lookups — never the wire. Eviction is explicit via `removeWindow`; capacity via `getOrPutDefault` (`error.CacheFull` at 512).
- tracking holds no facts: `getCurrentWorkspace` reads `model.current.index`; `allWindows` rebuilds a snapshot into a `store_capacity`-sized buffer; `isTiledMode`/`isOnCurrentWorkspace` read the store entry. Only boot-latched config (`workspace_count`) and two writes live locally: `removeWindow` (the facade's one drop transition) and clearing focus MRUs. Workspace switches mutate `model.current` in `actions.switchTo`.

**Implementation highlights.**
- `CacheMap`/`WindowData`/`live()`/`getOpt()` (wincache.zig:26-63); `title` is the sole owned (duped) field; `storeTitle`'s at-capacity drop for *new* windows while overwrites stay exempt (:280-296); `TitleCookies` (:164); `takePropertyReply` with wire-format validation (:257-272).

**Edges & contracts.** wincache consumers: border sweeps (steady-state zero XCB), admission cookies, `refreshTitle`, `peekHints` bridge into actions.mapRequest, unmanage eviction, the bar's draw path (bar.zig:792, 800). tracking consumers: spawn's workspace snapshot (correct for `[exec, switch_workspace]`), mapRequest current-ws, focus shouldRaise/collectVisibleWindows, floating isTiledMode, input click hit (via `findManagedWindow`, input.zig:231). # 13. `src/tiling/tiling.zig` — the tiling engine (SUB-SYSTEM CORE, soft core)

**Summary.** `tiling.zig` is the tiling subsystem's dispatch engine: a pure, xcb-free, allocation-free layer that resolves a workspace's config-selected layout down to a registry index and feeds a `contract.View` into the active layout module's `compute`, appending `contract.Placement`s. It owns config-name → registry-index resolution (`layoutByName`/`layoutKindFallingBack`), variant stepping (`cycleKind`/`variantCount`/`variantParse`), a size-hint application pipeline (`applyHints`), and the shared geometry helpers every layout consumes. When `has_tiling` is false the generated `tiling_seam` is an empty struct and the reconcile path runs no compute — all windows float by definition.

**How it works (high-level).**
- **Config text → kind u8.** `TilingConfig.layout` resolves once per seed in `seedParamsFromConfig` (:759): `layoutKindFallingBack(cfg.layout, 0)` (tiling.zig:247) case-insensitively matches `layoutByName` against the build-generated `tiling_mods` registry stems, warning and collapsing to the fallback (neutral index 0) when unresolvable. The `u8` lands in `model.LayoutParams.kind` (model.zig:69 — a bare index; the model stays registry-free). Variant strings go through the module's own `variant_parse` hook in `resolveVariant` (actions.zig:807).

- **Engine ↔ sync integration.** Engine: name resolution, kind stepping, view consumption, placement emission. # 14. `src/tiling/modules/` — the six layout modules (MODULES of the tiling sub-system)

**Summary.** The six layout modules under `src/tiling/modules/` are individually deletable registry entries, each binding `pub const module: contract.Layout` via the `tiling.layoutModule(name, icon, compute, extra)` helper. They all implement `pub fn compute(v: *const tiling.View, out: *tiling.List)` appending exactly one placement per window — visible via `emitRect`/`emitView`, or parked via `emitHidden`. `master`, `monocle`, `grid` are variant-carrying and bind `variant_parse` + `indicators`; `fibonacci` and `leaf` are single-variant; `scroll` alone binds the pure viewport addon (`slotWidth`, `maxOffset`, `preReconcile`). Parking is per-module, not a scroll-only behaviour (14.10): `master` parks stack columns past the width cap, `monocle` parks every window but the top one, `fibonacci`/`leaf` park the windows the BSP/fibonacci recursion has no room for, and `scroll` parks off-viewport slots. `grid` is the only layout that keeps every window visible. A placement is therefore a (rect, visible) pair, not a rect.

**How it works (high-level).** `tiling.compute(kind, v, out)` resolves the module by registry index and calls its `compute` — the only hook any of the six cares about. Geometry comes from `View` + the caller-resolved `Env` (margins, min_dim, primary_on_right, variant_idx). Variants are a `u8` index (`params.variant_idx`) into a comptime table each layout owns; `variant_count`/`variant_parse` make that table registry-driven for `cycle_variant` and config seeding. The scroll viewport is different in kind: a horizontal strip whose `params.viewport_offset` decides which slots are on-screen; its pure `preReconcile` duty (snap-right on count growth, then clamp) runs before `compute` at the pipeline choke point while the active layout is scrolled.

**Per-layout highlights.**
- **master — `"[]="` — variants `lifo`/`fifo`** (master.zig): master pane (fraction `primary_width`, or full width with no stack) + stack pane shrinking to the widest bounded slave's `max_width` (`minStackWidth`, :208); pane order flips via `env.primary_on_right` (:27). Heights distribute by water-filling (`fillHeights`, :126: pin `max_height`-capped windows and redistribute, dead slack centred); the stack is a capped-columns grid (column-major overflow; single column when `stack_n <= max_fit`, `tileStack` :228); columns past the width cap park via `emitHidden` (:293). `StackBoost` (:11) weights the top/bottom slot from `secondary_balance`. `module` (:327): `variant_count=2`, `fifo_variant=1`, `variant_parse = variantParse(&.{"lifo","fifo"})`, `indicators = &.{ "[N]", "=N=" }`.
- **monocle — `"[M]"` — variants `gapless`/`gaps`** (monocle.zig): fullscreen stack, only the topmost shown; `top_win = tiling.focusedElse(...)` so the last-focused window resurfaces on close; insets the whole workarea with a full gap iff `variant_idx == variant_gaps` (:7). `showOneHideRest` parks every other window. `module` (:29): `indicators = &.{ "<->", ">-<" }`.
- **grid — `"[+]"` — variants `rigid`/`relaxed`** (grid.zig): smallest-square grid (`calcGridShape` :66, `n==3` → 3×1), integer cells (`paneCell` :13). In `relaxed` mode a partial last row widens to share the full width. `emitOverflowShare` covers the overflow. `indicators = &.{ "[#]", "[~]" }`.
- **fibonacci — `"[@]"` — single variant** (fibonacci.zig): clockwise spiral — `SpiralDirection` (:10) encodes split-axis + forward/backward; each iteration halves the remaining region (`bisectRegion`) with one seam gap (`splitAndAdvance`, :69); a geometry-only gate falls to `emitOverflowShare` (:57). `module` (:110) is `layoutModule("fibonacci", "[@]", compute, .{})`.
- **leaf — `"BSP"` — single variant** (leaf.zig): recursive bisection of the longer axis 50/50, one gap per seam, borders only at leaf nodes (`tileRegion`, :22); a region unable to hold two `min_dim` children plus the gap degrades to `emitOverflowShare` (:46).
- **scroll — `"[|]"` — viewport addon** (scroll.zig): half-screen slots on a horizontal strip. `slotWidth` = `screen_w/2` (:16); `maxOffset` = `max(0, n*slot_w − screen_w)` (:23); `compute` (:31) clamps `params.viewport_offset`, places slot `col` at `col*slot_w − scroll` (full gap at screen edges, `seamGap` interior), floors content width at 1, parks fully off-viewport slots checked before the i16 cast (:78). `preReconcileHook` (:90) is pure value-in/out: grows visibility count past `viewport_prev_count` → snap `viewport_offset = max_off`, clamp, re-record count. `module` (:101) binds `slotWidth`/`maxOffset`/`preReconcile`.

**Edges & contracts.** `layoutModule` stamps `name`/`icon`/`compute` onto the module's `extra`; variants drive actions via `tiling.variantCount(kind)` + `stepVariantDir` (actions.zig:549). `master.fifo_variant = 1` marks fifo as the FIFO-spawn variant. Config value-strings resolve via `variant_parse` in `resolveVariant` (unparsable → warn + 0). Bar: the `layout` segment renders `tiling_mods[kind].icon orelse "><>"` (layout.zig:26); the `variants` segment renders `mod.indicators[params.variant_idx]` (variants.zig:24), both gated through `contract.activeLayoutKind`. Registry order is the alphabetical stem scan: fibonacci, grid, leaf, master, monocle, scroll.

# 15. `src/config/config.zig` + `fallback.zig` — the config facade (SUB-SYSTEM CORE, hard core)

**Summary.** `config.zig` is the interpreter facade of the config sub-system: it owns the *load pipeline* (read → join → parse → validate → typed `types.Config`), the *search-order* story (XDG/local dirs then files then embedded fallback), the *hot-reload* diff plumbing (`detectChanges` + `ConfigChanges`), and the *re-exec snapshot* machinery. It hands core a heap-allocated `types.Config` held by pointer; reload swaps that pointer atomically. `fallback.zig` supplies the embedded default TOML plus terminal auto-detection used to seed `auto_terminal` exec binds.

**How it works (high-level).**
- **File joining.** `loadConfigFromDir` (config.zig:251) auto-scans a config directory: collects all top-level `*.toml` entries (skipping directories and `fallback.toml` by name), sorts alphabetically, and merges each via `mergeOneFile` (config.zig:189) into one arena `parser.Document` (`mergeDocumentsInto`). Later files win on scalar conflicts; arrays accumulate. Sub-directories only reach the document via explicit `include = [...]` (`mergeIncludes`, :218, resolved one level deep — nested includes warned-skipped, keeping the graph cycle-free), and the `include` key is consumed so the unconsumed-key sweep doesn't flag it.
- **Load pipeline.** `parseAndBuild` (config.zig:599) hosts one load-scoped `ArenaAllocator`; while documents/their aliased file buffers live in the arena, `buildConfigFromDoc` (config.zig:654) dupes every owned string onto the caller's allocator. `buildConfigFromDoc` seeds from `getDefaultConfig` (:641 — `types.Config` field initializers as the single source of truth) then runs `parseKeybindings` → `parseTilingStructures` → `schema.applyAll` → `parseBar` → `parseRules`, then `warnUnconsumed` sweeps. A document with `had_errors` short-circuits to `error.ConfigParseFailed`. `validate` (:543) checks `master_width`'s ratio-vs-pixel policy.
- **Boot vs reload.** `load` (config.zig:1227) is the boot entry; the third `allow_pinned_snapshot` parameter admits the one boot-only override (the re-exec `HANA_CONFIG_DIR` pin) — reload must pass `false` so live edits always hot-reload. At boot a parse error falls back to `loadFallbackConfig`; on reload that propagation keeps the live config. `DefaultSource` (:371) reports user-vs-fallback so the reload path rejects a silent fallback swap. `loadFallbackConfig` (:611) parses the embedded TOML then substitutes `detectTerminal()` for `auto_terminal` exec strings.
- **Changes detection & atomic swap.** `detectChanges` (config.zig:1887) returns `ConfigChanges {bar, tiling, keys}` (:1782) via three hand-maintained content comparators; `keysChanged` compares only `(modifiers, keysym/button)` — an action-only edit needs no regrab. `handleConfigReload` gates subsystem rebuilds on these flags (see #2). The swap is a pointer exchange (`cs.config = new_ptr`, events.zig:345); the displaced config is deinit/destroyed after reload.
- **Re-exec snapshot.** Every successful load freezes the winning user source into a snapshot dir (XDG_RUNTIME_DIR-backed, `/tmp/hana-config-<uid>` fallback) via `refreshSnapshot` (config.zig:442); `reexecSnapshotPathZ` (:419) hands the one-shot `HANA_CONFIG_DIR` to `setenv` in re-exec, so a re-exec boots a byte-identical last-known-good config.

**Implementation highlights.** `config.load` (:1227); `loadConfigDefault` (:490) with `HANA_CONFIG_DIR` pin handling (:499); `buildConfigFromDoc` (:654) — section-ordering contract (workspaces.count precedes icon padding; base colors precede the `color_from` chain) + `warnMisCasedSections` (:706) + `warnInertSectionFamilies` (:730); `parseKeybindings` (:1074) — `Mod`/`kill` placeholders, `expandGlobKeys` `{...}` expansion (:878), `actionFromValue` (:969) with `+`→`.parallel` / array→`.sequence`, `parseBindString` (:1120); `action_map` (:797) auto-derived from the `Action` union tags; `schema.applyAll` (schema.zig:479); `detectChanges` (:1887); `refreshSnapshot` (:442); `fallback.getFallbackToml` (fallback.zig:59) + `detectTerminal` (fallback.zig:33) scanning a preference-ordered list via `paths.exeInDir`.

**Edges & contracts.** `types.Config` shape (types.zig:726). Consumers: core's `State.config` pointer; `input.buildKeybinds` at boot and pre-swap on reload; `actions.seedParamsFromConfig`/`applyConfigReload`; the bar's config copy re-pointed by `refreshConfig()`. Hot-reload: SIGHUP / `reload_config` → `events.handleConfigReload` (events.zig:289); ordering is load-bearing. Failure contracts: a `.fallback` source on reload is rejected; parse errors abort the swap so the live config survives. Re-exec: `HANA_CONFIG_DIR` stays set for process lifetime; the in-place reload path bypasses it; boot deinit is identity-guarded (main.zig:88).

# 16. `src/config/parser.zig` — the custom TOML reader (SUB-SYSTEM CORE, hard core)

**Summary.** `parser.zig` is a single-pass, line-oriented TOML reader with no external parser: a hand-rolled `Parser` scans the source into a pre-typed intermediate representation (`Value`/`Section`/`Document`). Duplicate keys (within a file and across merged files) accumulate into arrays with "later declaration wins" for scalar reads — the core distinction that makes `[binds]`, `include`, and multi-file joining work. It also owns the document-global color-palette fixpoint and the `+`/`(weight:N%)` color-mix machinery. Errors are warn-and-recover: a bad line sets `Document.had_errors`, prints `file:line:column`, and skips to the next newline.

**How it works (high-level).**
- **No separate lexer/parser split.** The `Parser` struct (parser.zig:826) carries only `content`, `pos`, `line`, `line_start`, `last_key`, `array_depth`, `*bool had_errors`. A top-level `parse` loop (:1234) skips blanks/comments; on `[` either rejects `[[...]]` (:1255) or parses a section header (`parseSection`, :928) swapping `current_section` (duplicate headers merge); otherwise parses one `key = value` pair (`parsePairs`, :1187). `parseString` (:964) handles a small escape set; `parseArray` (:998) recurses with depth cap 16; `parseBareToken`/`parseBareValues` (:1049/:1118) gather unquoted tokens — two or more become a literal array; a leading `#` stays a color while a later `#` is a comment. Section names are whole dotted strings in a flat `Document.sections` map — no dotted-key nesting at parse time.
- **Typing.** The `Value` union (parser.zig:17) is the IR: `.integer/.boolean/.string/.array/.color/.scalable`. Bare tokens classify in `parseBareTokenValue` (:1070): `%`-suffix → `ScalableValue.percentage`; bare decimal → `.absolute`; `#`/`0x` hex → `.color`; else int or a string slice into `content` (layout/action names need no quotes). Conversions: `Value.asScalar(comptime T)` (:50) and `asArray` (:77).
- **Error philosophy.** Every diagnostic goes through `warnLine` (:864) → `debug.warn` with `{path}:{line}:{column}:`; `skipBadLine` (:912) flags the document, warns, discards to next newline. Structural failures return `ParseError` (:796); `parsePairs` catches them naming `last_key`. Post-parse: `warnUnconsumed`, `getAsOrWarn` type warnings, `warnScalarDuplicate`.
- **Config-join hook.** `parse` (:1234) is invoked by `config.parseTomlFile`; `mergeDocumentsInto` (:775) is the cross-file merge accumulating duplicates via `insertOrAccumulate` (:742) and ORing `had_errors` → `error.ConfigParseFailed`.

**Implementation highlights.** `Value` (:17) with `lastScalar`/`asScalar`/`asArray`; `Section` (:85) with `pairs`/`consumed`/`keys_in_order`/`duplicated_keys`/`scalar_dup_warned` and `get`/`getAs`/`getAsOrWarn`/`warnUnconsumed` (:185-245); `Document` (:283) with `sections`/`root`/`palette`/`had_errors`; `accumulate`/`ensureArray` (:702-731) — the scalar/array duality that tags accumulated duplicates; color layer: `parseColor`/`hexPrefixLen` (:804-824), `colorFromValue` (:338), weight grammar `parseWeightPrefix`/`weightFromToken` (:380/:407), `extractMixOperands` (:455), `mixColors` (:566), `resolveColorExpr` (:608); palette: `collectPalette` (:652) — a bounded fixpoint over the four reserved names (:319) resolving literals, aliases and mixes; mixes capped at `max_mix_operands = 8` (:360).

**Edges & contracts.** Emits a pre-typed-but-not-domain-typed document (raw i64/bool/string/u32/ScalableValue; typed `Value` arrays). All interpretation (field mapping, palette, ratio bounds, keybind/rule/bar models) happens above it in schema.zig and config.zig. Everything borrows the load-scoped arena — `Document` owns nothing; merged values are shared, not copied. Known subset/limitations: `[[array-of-tables]]` headings are rejected with warn-and-skip (:1255); no TOML dotted keys or inline tables (binds' `{1-4,Q}` globs are handled above in `expandGlobKeys`); single-line strings with a small escape set; arrays depth-capped at 16; `%N` reversed-ratio not yet accepted; `#`-to-EOL comments with token-leading `#` always a color; colors accept `#RRGGBB[AA]`, `0x...`, bare 6/8-digit hex, palette names, and `+` mixes.

# 17. `src/config/types.zig` + `schema.zig` — the config schema & types (SUB-SYSTEM CORE, hard core)

**Summary.** `types.zig` holds the *typed config model*: every struct the runtime consumes (`Config`, `TilingConfig`, `BarConfig`, `WorkspaceConfig`), the `Action` union, `ScalableValue`, `Color`, `Keybind`/`MouseBind`, per-workspace override records, plus single-sourced section/color constants. `schema.zig` is the comptime field-level validator/coercer: an ordered `knobs` table declares every scalar knob once and `applyAll` walks the parser's `Document`, coercing keys into the typed `Config` with warn-and-revert (never clamp) semantics — replacing the old hand-written per-section scalar interpreters.

**How it works (high-level).**
- **Type model.** `Config` (types.zig:726) owns `keybindings`/`mouse_bindings`, `tiling: TilingConfig`, `workspaces: WorkspaceConfig`, `bar: BarConfig`, plus gate flags `fullscreen_enabled`/`drag_enabled` and `snap_distance`. Heap-owning fields get a hand-written `deinit` (types.zig:742) because the parser's arena is reclaimed after build.
- **Schema-driven coercion flow.** `buildConfigFromDoc` runs `parseKeybindings` → `parseTilingStructures` → `schema.applyAll` (all scalar knobs + `[bar.properties]`) → `parseBar` → `parseRules`. `applyAll` (schema.zig:479) iterates `knobs` in table order (order matters: `workspaces.count` precedes icon padding; base bar colors precede the `color_from` chain), resolves the dotted target path comptime-typed via `PathType`/`ptr` (schema.zig:277/:286), and dispatches on `Kind` (schema.zig:217). `requires` gates see whether the parent section is present in the document.
- **Unknown keys / duplicates / bad values.** Sections track `consumed` sets; `warnUnconsumed` flags stragglers. Duplicates accumulate into `duplicated_keys` and warn once; mis-cased sections get a dedicated sweep (`warnMisCasedSections`, config.zig:706). Bad values never throw — `getAsOrWarn` warns and ignores, or range helpers (`getInRange` schema.zig:322) warn-and-return the default; a `had_errors` document becomes `error.ConfigParseFailed`.
- **Cross-cutting types.** `Action` union (types.zig:96): `exec`, `close_window`, `reload_config`, `reload_hana`, `cycle_layout`, `toggle_bar_visibility`/`toggle_bar_position`, `set_master_width`/`set_master_count`, `grow_stack`, `toggle_floating_window`/`toggle_fullscreen`, `swap_master`, `switch_workspace`/`move_to_workspace`/`toggle_tag`, `sequence`/`parallel`, `dump_state`, `minimize_window`/`unminimize: RestoreOrder`/`unminimize_all`, `cycle_variants`, `toggle_prompt`, `all_workspaces`, `pin_window`, `cycle_focus`/`move_window_next`/`move_window_prev`, `scroll_view` + `Dir`-carrying variants; `RestoreOrder` aliased from `model.RestoreOrder` so config and runtime share one enum (types.zig:94). `ScalableValue` (types.zig:14), `Color = u32` (:28), `Keybind`/`MouseBind` (:164-176) — keysym↔keycode resolution deliberately NOT here (needs live XkbState; breaks type cycles).

**Implementation highlights.** `Config` (:726) with per-section deinit (:742); `TilingConfig` (:246) — `layout` (canonicalized at the boundary via `canonicalLayoutName`, config.zig:1255), `master_width`/`master_count`, `variants` map, per-workspace overrides, and shared last-wins lookups (`masterCountLookup`/`workspaceLayoutLookup` :288/:303); `BarConfig` (:462-698) — palette (4 window-state colors doubling as doc-global palette vars), segment fg/props maps, `BarLayout` columns, derived getters; per-workspace override records (:230-240); schema builders — `knob`/`knobGated`/`tilingAesthetics`/`masterStack`/`barScalable`/`barPlainColor`/`barTitleColor`/`barDrunColor` (the `color_from` chain with `copy_when_absent`) and `enum_read` off `types.enumFromString` (:204, used by `MasterSide`, `BarScreenPosition`, `IndicatorLocation`); `[bar.properties]` composite entries via `applyBarProperties`/`applySegmentEntry` (schema.zig:585/:675) parsing mixed color + `underline`/`bold`/`italic`.

**Edges & contracts.** `core.State.config` is the single consumer handle (core.zig:103/110 read `tiling.enabled`/`border_width`); pipeline builds the tiling env via `tilingEnv`. input builds the dispatch map from `config.keybindings` (resolving keysyms→keycodes against live XKB); mouse binds grabbed from `config.mouse_bindings`. `actions.seedParamsFromConfig` consumes `TilingConfig` incl. both override lookups and the `variants` value-strings fed to each layout's `variant_parse`. `window.buildRulesMap` iterates `config.workspaces.rules` (`types.Rule`: class→workspace or "float"). The bar draws wholly from `BarConfig` (metrics font_size, drawing fonts, win position/transparency, title carousel_enabled, prompt vim_mode). The four `palette_*_color` names (types.zig:82-85) are the document-global palette vars referenced from any color knob; `[bar.properties]` entries are what theme files carry.

# 18. `src/input/input.zig` — the input sub-system (SUB-SYSTEM CORE, hard core)

**Summary.** `input.zig` is hana's input event layer: it owns XKB initialization/state (`xkb_state`, `initXkb`/`getXkbState`), the `(modifiers, keysym) → Action` dispatch map (`keybind_resolver`, built by `buildKeybinds`, rebuilt on reload), and all key/button/motion event handling including the Super+Button synchronous-grab mouse machinery and the "bar vs managed-window" click split. Keypresses route first through the chrome overlay's key handler (consuming keys while the prompt is active) and only then to `executeAction`.

**How it works (high-level).**
- **Lifecycle.** At boot, `setup` (:97) runs `setupGrabs` (:105) placing SYNC-mode `Super+Buttons{1..5}` grabs on root across all 8 `masks.lock_modifiers` combinations, and applies the cursor theme (`XcbCursor.setupRoot`, xcb-cursor externs hand-declared). `initXkb` (:43) builds a flat keycode→keysym table; `deinitXkb` (:48) tears it down. `buildKeybinds` (:64) runs `keybind.resolveKeycodes` then `rebuildDispatchMap` — at boot and pre-swap on every reload. `deinitKeybinds` is released before the config's Actions are freed.
- **Key dispatch flow.** `events.zig`'s comptime table routes KEY_PRESS→`handleKeyPress` (:140): normalize modifiers, resolve the keycode to a keysym via the state, O(1) `keybind_resolver.lookup`, then `surfaces.chromeHandleKeypress(event, matched)` first — if true the overlay consumed it and the binding never fires. Otherwise `executeAction`. Bare modifier presses are dropped silently; latency is tracked by `key_profile` (:132), compiled out unless `build_options.profile_key`.
- **Mouse flow.** `handleButtonPress` (:196) keys off `super_held`: a plain click on the bar routes to `handleBarButtonPress` (:210) → `surfaces.handleButtonPress`; everything else goes through `handleWindowButtonPress` (:219): scroll binds (4/5) first, then `window.findManagedWindow`; a bare click focus-grabs + releases; a Super click tries `tryConfigMouseBind`, else starts a drag (`actions.startDrag` + `keepDragGrab`), else `releaseGrab` (REPLAY_POINTER) so the frozen click lands in the app. Motion feeds `actions.updateDrag` while dragging, or the bar scrub path.
- **Reload vs kept.** Rebuilt: dispatch map + resolved keycodes (on reload and mapping-notify). Kept: `xkb_state` (process-lifetime, non-null during reload), root mouse grabs, focus's last-event-time. `handleMappingNotify` (:83) rebuilds the keysym table, re-resolves keycodes, calls `events.grabKeybindings()`.

**Implementation highlights.**
- `KeybindResolver` (keybind.zig:21): `AutoHashMapUnmanaged(u64, *const types.Action)` keyed by `dispatchKey = (mods << 32) | keysym`; `rebuildDispatchMap` (:30) warns on shadowed duplicates; `lookup` (:55) is the O(1) hot path. Module-owned here so the pure config layer stays X-free.
- `executeAction` (:329): one switch over the `types.Action` union. `.sequence` runs strictly in order with `.exec` members synchronous (`spawn.execSynchronous`); `.parallel` fire-and-forget; `.reload_config` → `utils.reload()`. `tilingOp` (:399) wraps tiling mutations in `setSuppressReason(.tiling_operation)` + `beginTilingOpSettle`. `tryConfigMouseBind` (:444) executes `toggle_floating_window` against the clicked window, everything else against the keyboard-focused window.
- `closeWindow` (:294): ICCCM §4.1.2.7 `WM_DELETE_WINDOW` client message with `focus.getLastEventTime()`, falling back to `xcb_destroy_window`.
- XK vocabulary: input.zig itself never touches `XK` (core.zig:14) — that enum is the chrome overlay's keysym vocabulary; config parsing resolves names via `keysyms.keysymFromName` (pure, xcb-free).

**Edges & contracts.** Routing in via `events.zig` `dispatch_table` (:115) with comptime-checked handlers. Actions *borrow* from config: map entries are `*const Action` into the live config — why reload ordering is load-bearing (`buildKeybinds` pre-swap, pointer swap at events.zig:345, `grabKeybindings()` post-swap because `fillGrabCookies` reads the live config). Chrome overlay: `surfaces.chromeHandleKeypress(event, matched)` before keybind dispatch (true = consumed); all gated by `build_options.has_bar`. Keysym values are raw XKB codes matched verbatim; held-key auto-repeat handled by xkbcommon's detectable-auto-repeat flag so held binding keys re-fire instead of flapping a toggle.

# 19. `src/input/` keybind/XKB support — `keybind.zig` + `keysyms.zig` + `xkbcommon.zig` (SUB-SYSTEM CORE, hard core)

**Summary.** The keybind/XKB triad converts configured `(modifiers, keysym) → Action` bindings into an O(1) hot-path dispatch map resolved against a live `XkbState`. `keybind.zig` owns the `u64`-keyed dispatch map and keysym→keycode resolution; `xkbcommon.zig` wraps libxkbcommon/xkbcommon-x11 into a flat lock-insensitive keycode→keysym table; `keysyms.zig` is a tiny xcb-free namesym vocabulary so the pure config layer can parse binding names without importing the live-device-state module.

**How it works (high-level).**
- **keybind.zig:** `KeybindResolver` (keybind.zig:21) is a `std.AutoHashMapUnmanaged(u64, *const types.Action)`, key = `(modifiers << 32) | keysym` (`dispatchKey`, :24). `rebuildDispatchMap` (:30) rebuilds from `[]types.Keybind`, warning-and-overwriting on conflicts; `lookup` (:55) is the O(1) get. `resolveKeycodes` (:70) mutates each binding's `keycode` from the XKB table, warning when a keysym has no base keycode (shifted symbols like `@` must be bound via `2`).
- **keysyms.zig:** `XKB_KEY_NoSymbol` (:15), `keysymFromName` (:20, case-insensitive), `keysymGetName` (:27). Used by the config parser at load time, never at runtime. Imports only `xkbcommon.h` (xcb-free).
- **xkbcommon.zig:** `XkbState` (xkbcommon.zig:95) keeps an `xkb_context` and a flat `keysym_by_keycode: [256]u32` table (1 KiB inline, no allocator). `init` (:109) creates the context, negotiates the XKB extension, enables detectable auto-repeat, obtains the core keyboard device id, builds the table. It retains no keymap/xkb_state handle — dispatch resolves purely from the flat table. A press becomes an action by: `handleKeyPress` → `normalizeModifiers(event.state)` → `XkbState.keycodeToKeysym(event.detail)` (:151) → `lookup(mods, keysym)` → `executeAction`.

**Implementation highlights.** Modifier normalization masks with `masks.mod_mask_binding` = shift|ctrl|alt|super (masks.zig:21); lock handling is not in the map but by grabbing each key 8× per `masks.lock_modifiers` combination (events.zig:228). `baseSymbol` (xkbcommon.zig:78) reads the level-0 symbols directly — a lock-sensitive read would let a CapsLock held at startup pin shifted symbols; `buildKeysymTable` (:87) covers the X11 range 8..255. `withRetries` (:192) backs `retrySetup`/`retryDeviceId`/`retryKeymap` (3 attempts, raw `nanosleep`); `keymapHasEnoughSymbols` (:248) rejects a not-yet-ready keymap with <40 reachable symbols. `enableDetectableAutoRepeat` (:38) sends `xcb_xkb_per_client_flags` (best-effort). `keysymToKeycode` (:161) linearly scans the L1-cached table.

**Edges & contracts.** Ownership: `input.zig` holds both singletons (`xkb_state`, `keybind_resolver`); `getXkbState` never cached across deinit. Grabbing: `events.grabKeybindings` ungrab-all then checked `xcb_grab_key_checked` grabs, verified in one `request_check` batch. Config reload: rebuild pre-swap, regrab post-swap. Mapping changes: `XKB_MAPPING_NOTIFY` → rebuild table (failure keeps the old mapping) → re-resolve keycodes → regrab. The flat level-0 table is both dispatch source and grab source: grabs cover all 8 lock combos, matching normalizes locks away — dispatch lock-invariant, grabs still accessible under any lock state.

# 20. `src/bar/bar.zig` + `refresh.zig` + `win.zig` — the bar orchestrator (SUB-SYSTEM CORE, soft core)

**Summary.** `bar.zig` is the bar sub-system's composition root: it binds the `contract.Surfaces` value (bar.zig:1885) that core's event loop and pipeline call through, and owns the entire orchestration surface — window creation, config/height resolution, segment-registry dispatch, the dirty-tracking redraw pipeline, refresh cadence, visibility wire-glue, input routing, and the screen claim. `refresh.zig` is the RandR refresh-rate detector/publisher (the bar's only consumer is its own render pacing), and `win.zig` is the bar's X11 client-window lifecycle (creation, EWMH dock props, ARGB visual, draw-context wiring). All segment logic is external: the file iterates the build-generated `bar_modules.modules` registry (bar.zig:65) via uniform loops and never names a module.

**How it works (high-level).**
- **Loop shape — fully event-loop-hooked, not self-ticking.** The bar owns no poll loop; core's `events.run()` drives it: `pollTimeoutMs` (:261) contributes the poll deadline, `onPollWakeup` fires on timer wakes, `updateIfDirty` runs after every X batch, `updateClock` each iteration, and the RandR hooks forward extension events + deferred re-detection.
- **Segment discovery.** `bar_mods = @import("bar_modules").modules` (bar.zig:65), build-generated `[]const contract.Segment` in deterministic sorted-stem order. Capability roles resolved at file scope: `self_ticking_ids` and `center_slot_ids` (bar.zig:67-68); `title_id` is the first center-slot binder (:74). Configured names in the config layout tree resolve via `segId`→`segAt`; an empty registry folds loops away at comptime (:92).
- **Fact-revisions → dirty segments.** `Facts` (bar.zig:514) caches last-drawn core revision counters seeded to `maxInt(u32)` so the first update draws. `updateIfDirty` (:1649) diffs `core.focus/window/layout.rev()`: focus → `markDirtySource(.focus)` (title-only, via each module's declared `dirty_sources` bitmask), window → `markDirty()` (whole bar), layout → `requestFullRedraw()`. A fullscreen-rev check runs even while hidden. `Dirty` (:422) is one bool per slot + a whole-bar flag; every slot starts dirty so the first draw is a full background clear.
- **Slot/frame layout.** Config rows are `types.BarLayout` items with `.left/.center/.right` anchors. `drawAllInner` (:980) measures the right cluster once into `RightCluster` scratch (:387), then lays out from x=0 leftward and backward from the right edge. A center row computes `centerRowBudget` (:146), reserves the row's non-center segments out of a clamped `avail` (floored at `title_min_width`), and splits the remainder evenly among center-slot segments via `centerShare` (:135).
- **Refresh rate / RandR.** `ensureRefreshRateDetected` subscribes to screen/CRTC/output notifications. A CRTC-change RRNotify resolves the newly-active mode id against a cached mode table with zero round-trips (`handleRandrNotifyEvent`, refresh.zig:94); anything else is debounced (100 ms) into a deferred full re-detect (`runPendingRedetect`, pipelined into ~3 blocking waits despite output count, refresh.zig:246). Rates outside 10-1000 Hz are rejected (`publishDetectedRate`, refresh.zig:309); `detectedHz` publishes atomically for lock-free render pacing.
- **Visibility.** Pure decisions in `visibility.zig` (`desiredVisibility`, `shouldBeVisible`); bar.zig keeps the X glue (`applyVisibility`/`applyVisibilityDecision`, :1562/:1638): map/unmap ordering, `onBarShown` fan-out, screen claim, optional in-grab reconcile. Fullscreen hides arrive in-grab via `hideBarForFullscreen` (:1617); workspace switches pre-apply visibility without reconcile (`updateBarVisibilityForWorkspace`, :1609); user toggle via `setBarState` (:1546); prompt force-show via `presentForPrompt`/`dismissAfterPrompt` (:1502/:1530).

**Implementation highlights.**
- `bar.init` (:1222): asserts enabled, `barwin.initAtoms()`, `ensureRefreshRateDetected`, `calcBarHeightAndFontSize` (:225, incl. the 100pt percentage-font probe `resolvePercentageFontSize`, :204), `createBar` (:1196 → window + DrawCtx + State), `screen.setSurfaceWindow`, maps before first draw, then runs each segment's `init` with the file-scope `g_bar_handlers` (:341). `deinit` (:1254) reverses.

**Edges & contracts.** The `Surfaces` contract (contract.zig:79) — bar binds: init/deinit, handleExpose, updateIfDirty, pollTimeoutMs, onPollWakeup, updateClock, randrFirstEvent/handleRandrEvent/runPendingRedetect, onReload, refreshConfig, chromeHandleKeypress (:283, anyBoolHook first-true), isBarWindow, handleButtonPress/Motion/Release (bounds hit-test + onClick/onScroll/onDragMotion/onDragEnd dispatch), setBarState, hideBarForFullscreen, updateBarVisibilityForWorkspace, toggleBarSegmentAnchor (:1348), chromeToggleOverlay (:293). # 21. `src/bar/` segment core — `segment.zig` + `segdraw.zig` + `metrics.zig` + `visibility.zig` (SUB-SYSTEM CORE, soft core)

**Summary.** `segment.zig` is the bar's shared, type-free vocabulary: `Frame`, `DrawCtx`, the title render/snapshot machinery, plus registry role/capability lookups the orchestrator dispatches through. `segdraw.zig` is a comptime builder collapsing the icon-ish modules' cached-width tracking and hook wiring into one `module()` constructor; `metrics.zig` holds the bar-owned derived font-size state; `visibility.zig` is the pure decision half of bar visibility (the eponymous bar.zig keeps all X11 glue). Together a soft core: each is directly consumed by the bar's segment modules, but nothing above them is required for the WM to function.

**How it works (high-level).** Every draw, `bar.zig` builds one shared per-frame `DrawCtx` (`frameCtx` bar.zig:1097, then `fillDrawCtx` :774 fills the live `Frame` and title snapshots), scans the config layout tree, measures each segment's reserved width via the uniform `naturalWidth` hook, pins it into `ctx.width`, calls `draw(ctx, x)`, and records click bounds. All drawing targets `drawing.DrawContext`'s off-screen pixmap, then `queueBlit`/`blitRegion` ship `[x, x+w)` with `xcb_copy_area`. Natural-width probing has two paths: `probeFontMetrics` on a throwaway 1×1 image surface for bar height (drawing.zig:834); per-segment row widths from the `naturalWidth(frame, clock_width)` hook. Visibility is decided purely: `desiredVisibility(ws, is_visible, is_globally_visible)` folds a fullscreen forced-hide with the user toggle; bar.zig applies map/unmap + claim + reconcile.

**Implementation highlights.**
- segment.zig: `BarHandlers` (:28) and `MinimizedApi` (:53) — the one-way bar→segment service seams; `Frame` (:40) — the "only segment-visible slice of WM state" (ws count/current/all-view/has-windows), collected by `scanLiveFrame` (bar.zig:814); `castDraw` (:65) — the single `*anyopaque → *DrawCtx` cast; `DrawCtx` (:75) with `titleRenderContext` (:102)/`titleSnapshot()` (:114); title machinery: `title_min_width` (:131), `max_visible_windows` (:135), `GatherScratch.gather`/`compareWindows` sort (:230/:218), pixel-perfect `segmentBounds`/`segmentIndexOfX` (:251/:260), pure `hitTest` (:271); registry tools: `hasSource` over `DirtySources` bits (:302), `idByName` (:311), comptime `findAllByCapability` (:325).
- segdraw.zig: `widthState(tag)` (:17) per-module cached width + `redraw_pending` folding; `keyedWidthState` (:49) adds a mode key (the clock's reservation) with probe-width fallback; `drawAndStore` (:84) — shared "padded segment + width store" draw body; `module(name, draw, action, opts)` (:166) assembling a `contract.Segment` (`drawHook` :136 casts via `castDraw`; `clickHook` :148 steps direction + redraw; `natural_width` defaults to `passthroughWidth` when a `measureString` is set).
- metrics.zig: `default_scaled_font_size` (:21) embedded in `default_fallback_font` (:25); `scaled_font_size` (:28) runtime state; `recompute()` (:41) = `scale.scaleFontSize(config.bar.font_size, screen)`; writer `calcBarHeightAndFontSize` (bar.zig:225), reader `buildSizedFontList` (drawing.zig:855).
- visibility.zig: `barForcedHiddenByFullscreen` (:21) comptime-folds to false without the fullscreen module, else `model.coveringOccupantOnWs`; `shouldBeVisible` (:31); `desiredVisibility` (:45) returning a `DesiredVisibility` carrying `needs_change` so bar.zig skips wire work on no-op; `keepPromptOverride` (:62) re-derives visibility at prompt exit. No hover/autoshow logic here — state + map/unmap live in bar.zig.

**Edges & contracts.** The `*anyopaque` seam: `contract.Segment.draw` is `fn(*anyopaque, u16) anyerror!u16`; the bar passes `&DrawCtx`, segments cast back via `castDraw`; `naturalWidth` receives `*const anyopaque` = `&ctx.frame`; `onClick` receives `*State` plus the title-click trampoline. Note: there is no bar-side `Env` — the contract comment names it but the actual vocabulary passes `Frame` inside `DrawCtx`; `Env` exists only in the tiling `Layout`/`View` vocabulary. Only bar.zig builds `Frame`/`DrawCtx`; segments consume via the registry and call back only through `BarHandlers` and the redraw/title fns. Clickable bounds: `recordClickBound` (bar.zig:735) during the layout pass; `handleButtonPress` walks bounds first-match; the title resolves windows with `segmod.hitTest` on the cached snapshot.

# 22. `src/bar/drawing.zig` — the cairo/pango renderer (SUB-SYSTEM CORE, soft core)

**Summary.** drawing.zig is the bar's off-screen paint layer: it owns the Cairo/Pango/GLib extern bindings (declared `pub extern fn` since headers may be absent), the `DrawContext` that proxies the bar's X window onto an off-screen X pixmap, and every primitive segments use to draw — XCB rectangle fills, baseline-anchored Pango text with per-segment style attributes, sized indicator glyphs, and the `xcb_copy_area` blit back to the window. All colors/fonts/padding/metrics arrive via `types.BarConfig`; all text is utf8 Pango-shaped so emoji/icon glyphs get per-glyph fallback.

**How it works (high-level).**
- **Paint pipeline.** `performDraw` → `drawAllInner` clears the whole background via `clearRegion` (only on a full redraw), walks config layout rows, dispatches each repaintable segment's `.draw` hook. Each segment paints into the off-screen `DrawContext` and returns its advanced x; bar.zig records clickable bounds as it lays out. Finally `queueBlit` (:1164) flushes the cairo surface and enqueues one `xcb_copy_area`; no `xcb_flush` until end-of-batch. Partial repaints (`redrawSlotScoped`, bar.zig:1453) clear the slot, redraw one segment, blit `max(bound_w, drawn_w)`.
- **Text shaping.** One shared `PangoLayout` per DrawContext receives text via `pango_layout_set_text` (utf8-aware); painted at the baseline by `showLayoutAtBaseline` (:294) via `pango_layout_get_baseline`. Styling (underline/bold/italic) encoded as a one-shot `PangoAttrList` by `buildStyleAttrs` (:309). Fonts are Xft config strings converted to Pango form by `convertFontName` (:924). Text measurement is the same draw path minus paint (`measureTextWidth`/`Styled`), so bold/italic reserve the right width.
- **Color/theme.** Cairo colors are 0x00RRGGBB unpacked by `setCairoColor` (:255). Rect fills deliberately bypass Cairo: `fillRect` (:484) uses `xcb_poly_fill_rectangle` and, under ARGB, packs **straight alpha** (picom expects straight alpha while Cairo's XRender backend writes premultiplied), with a `last_gc_color` cache skipping `xcb_change_gc` for adjacent same-colored segments.
- **Hitboxes.** `recordClickBound` is called per layout-placed segment with its measured width; `handleButtonPress` walks these bounds first-match and dispatches to `onClick`; the title's pixel-level hit-test is pure in-process `segmod.hitTest` against the last frame's snapshot.

**Implementation highlights.**
- `DrawContext` creation: `initWithVisual` (:376) — depth 32 iff ARGB (a `0` COPY_FROM_PARENT depth would BadValue on create-pixmap, :393), resolves the visual via `resolveVisualType` (:897), creates pixmap + `cairo_xcb_surface_create` + pango layout, batches two checked GC creates (fill GC on pixmap, copy GC on window). `deinit` (:448) frees the surface before the pixmap.
- Text helpers: `drawText`/`drawTextEllipsis` (:559/:592), `drawTextScrolled` (:566, cairo save/rectangle/clip then two x-positions for marquee tiling), `drawTextSized` (:511, cached absolute-size font descriptors), `drawTextStyled` (:665), `measureTextWidth`/`Styled` (:629/:658), `baselineY` (:711).
- Per-segment entry: `paintedSegment` (:722) — apply style props, measure, fillRect bg, paint text at baseline, return advanced x; `drawPaddedSegment` (:752) adds config padding + `segmentFg`, with a `cover_text` min-width so narrower region repaints wipe wider earlier frames; `drawPaddedSegmentValue` (:783) splits a numeric subslice into `segmentValueFg`. Consumed by clock, slider, systatus, tags.
- Blit: `blitImpl` (:680) = `cairo_surface_flush` + `xcb_copy_area`; `queueBlit` (no flush, safe in `xcb_grab_server`) vs `blitRegion` (immediate flush, for timer-driven clock/caret paths).
- `probeFontMetrics` (:834) on a 1×1 image surface; `FontState.getMetrics` (:240) caches (ascent, descent).

**Edges & contracts.** Consumes `segmod.DrawCtx`/`Frame` + `BarConfig` + scaling accessors. Callers: bar.zig, win.zig, and every segment through the uniform `.draw` hook; font/DPI flow from metrics.zig. Repaints are partial by design; a full redraw only when the whole dirty set is set (sole background-clear). Segment draw calls advance a shared x cursor and return errors instead of propagating (a broken segment draws nothing but still consumes its reserved slot). The failed-font-reload path keeps the old DrawContext alive; sized-font caches key on the base font-description pointer identity to stay correct across reloads (:521).

# 24. `src/bar/modules/title/` — title MODULE + carousel MODULE EXTENSOR

**Summary.** The **title** segment is the bar's center-slot module: it claims the reserved center region, renders the focused window's title (from `wincache.peekTitle` via the bar's DrawCtx snapshot), and is clickable to focus/minimize/restore (title.zig:368-378). When a title overflows its slot, **carousel** extends it into a threadless marquee on the monitor-refresh cadence. The extension is build-time: title imports only a type (`Scroller`) plus the generated `title_subs` registry, never the carousel module itself; dropping carousel.zig silently degrades overflow titles to static ellipsis.

**How it works (high-level).** Every title draw runs `drawInner` (title.zig:66), which primes RandR detection (`refresh.ensureRefreshRateDetected`, :70). The per-frame `TitleSnapshot` renders as either a single focused-window cell (`drawSingleWindow`, :97) or a split view of tiled cells (`drawSegmentedTitles`, :238). Each cell computes geometry (`titleTextGeom`, :197), measures `text_w` against `avail_w`, and reaches `drawFittedTitle` (:207): fitting titles draw statically; overflowing ones with `scroll_enabled` hand off to `drawMarqueeCell` (:142); the rest get `drawTextEllipsis`. Only the focused cell passes `scroll_enabled = true`, so the carousel tracks exactly one cell per frame. The carousel is elapsed-time-based and single-threaded: `offsetFor` (carousel.zig:77) hashes the title (Wyhash), keeps a `(active_win, active_hash)` identity so a focus change/rename restarts, advances `offset_px += speed_px_s * dt/1000` wrapped by `@mod` over one `cyclePx` = text width + 48px gap (:39). Frame cadence: `pollTimeoutMsHook` (title.zig:331) reports `pollDeadlineMs(now, carousel_enabled, refresh.detectedHz())` — one display period `ceil(1000/hz)`; `needsRepaintHook` (:355) forwards `scrollingActive()`, which the bar honors to keep the slot out of the snapshot-diff skip, with a marquee-only fast path reusing the cached `last_ctx`. `onBarShown` forwards to `resetForShow` (:363), pivoting `last_frame_ms` to "now" so motion resumes without teleporting across the hidden gap (carousel.zig:92-99).

**Implementation highlights.**
- title.zig: `Scroller` struct (title.zig:24-30) — the extension-seam fn-pointer contract (`cyclePx`/`scrollingActive`/`offsetFor`/`resetForShow`/`pollDeadlineMs`); `scroller` const (:31-34) = `if (@import("title_subs").addons.len != 0) @import("title_subs").addons[0] else null`; `overlay` const (:39-42) = `contract.providerOf(Segment, bar_modules, .overlay)` (the prompt); `drawMarqueeCell` (:142-179); `drawSegmentedTitles` (:238-282, only `is_focused_win` becomes scroll_enabled); `drawHook` (:292-306) latches `overlay_was_active` and pivots the scroller on overlay close; `onClickHook` (:308-325): right-click toggles overlay, left-click routes `handleTitleClick` (hitTest → restore/minimize/focus); `naturalWidthHook` (:327) returns `title_min_width` (100) clamped by `centerRowBudget`; `module` binding (:368-378): `name="title"`, `center_slot=true`, `dirty_sources = {focus, frame}`.

# 26. `src/bar/modules/slider/` — slider MODULE + brightness/volume MODULE EXTENSORS + native backends

**Summary.** `slider.zig` is the closed core of the slider package: it owns the generic per-control shell (arm/poll lifecycle, draw, click/scroll/drag interaction, coalesced commit scheduler) while every device control — `volume`, `brightness` — is an open sibling binding a `Sub` value exposing only its backend truth, read/write, and display format. build.zig promotes each bound sibling to its own independent `contract.Segment` via `segmentFor(i)`. `brightness.zig` writes sysfs directly (un-throttled) and shells out to rate-limited `brightnessctl` only as a permission-denied fallback; `volume.zig` probes four backends most-native-first (native libpulse → `pactl` → native ALSA ioctl → `amixer`). `native_alsa.zig` is a dependency-free kernel-ABI backend (raw `/dev/snd/controlC*` ioctls, no libasound); `native_pulse.zig` is a zero-link-time libpulse wrapper via `std.DynLib`. Neither native backend binds `Sub`, so neither is promoted to a bar segment.

**How it works (high-level).**
- **Model.** Each control exposes a single `u8` level 0-100 (clamped `@min(v,100)` at every commit) plus optional presence (`has_value`) and write gate (`writable`). The core keeps only slot geometry/arming/cadence in `Instance` (slider.zig:301); each control keeps its own cached state in the sibling file.
- **Render.** `drawFor` (:415) arms on first draw (one `read()`, schedules `next_read_ms`), returns a zero-width no-op while `has_value` is false, paints `drawDragBar` (:398) while scrubbed, else the idle label through `drawPaddedSegmentValue`. The painted width feeds `slot_w`, the click hit-test bound and slider denominator.
- **Interaction.** Wheel steps ±2% (`scroll_step` :65) with a boundary no-op; left press enters exclusive drag mode, one-shot `apply`s the position-mapped level, resets the throttle; press-hold scrubs per motion; release fires `onDragEnd`, force-flushing pending commits and re-reading truth. Right-click dispatches the sub's `secondary` (volume's mute toggle).
- **Commit pipeline.** Each motion/scroll calls `commitPreview` (:346): optimistic `preview(pct)` plus `Throttle.apply` — native commits (`commit_is_native()`) land immediately un-throttled; subprocess spawns are rate-limited to 80 ms with an inside-window event marked `pending` (coalesced onto the newest value), flushed by the poll sweep or drag end.
- **Sub-extensor seam.** Siblings self-declare `pub const sub: slider.Sub`; build.zig filters by that role marker; a control is *enabled* merely by file presence plus its name in a bar layout — config keys (`volume_format`, `brightness_device`, etc.) only restyle/select, they don't enable.

**Implementation highlights.**
- slider.zig: `Sub` (:260-299); registry `const subs = @import("slider_subs").subs` (:63); per-control state arrays (:315-321); `Throttle` (:86-132, `apply`/`reset`/`flushOwed`/`finish`, `land` does the actual write); `rawFromPct`/`pctFromRaw` (:140/:148) shared linear map; `pctFromSlot` (:326); `spawnCapture`/`runOut`/`runOk` (:160-185, allocation-free `/bin/sh`); `renderLineValue` (:206) substitutes `{pct}`/`{state}` recording the numeric region for the two-color split; `drawFor` (:415)/`drawDragBar` (:398)/`onClickFor` (:449, left enters drag, right→secondary)/`onScrollFor` (:477)/`onDragMotionFor` (:509, scoped redraw deliberately NOT full-bar)/`onDragEndFor` (:519, `throttle.finish` + read + exit drag); `pollDeadlineMsFor` (:357, earliest of read and owed flush, `max_cadence_ms` 5000); `segmentFor(comptime i)` (:533-583).

# 27. `src/bar/modules/prompt/` — prompt MODULE + vim MODULE EXTENSOR

**Summary.** `prompt.zig` is the bar's inline command prompt: a full line editor overlaying the title slot via the `contract.BarOverlay` seam, grabbing the keyboard while active, and routing every key through `chromeHandleKeypress` before keybind dispatch. It executes the typed command through `spawnCommand` (double-fork `setsid` + `/bin/sh -c`), persists history with mode 0600, and offers ghost completions from history plus `$PATH` executables. `vim.zig` is a module extensor: it never participates in the overlay lifecycle directly; it binds vim-modal handlers into prompt.zig's `Handlers` function-pointer seam (via the build-generated `prompt_subs` registry), so deleting vim.zig reverts the prompt to basic readline-style editing with no core edits.

**How it works (high-level).**
- **Overlay lifecycle.** The prompt is a registry `Segment` with `.name="prompt"` and an `.overlay` value of type `contract.BarOverlay` (`is_active`/`toggle`/`draw`/`needsRepaint`). The title module finds it name-free (title.zig:39) and delegates the whole slot to `o.draw` while active. Opening: `.toggle_prompt` action → `surfaces.chromeToggleOverlay()` → the title's right-click `onClickHook` → `o.toggle()`. `activate()` (prompt.zig:600) `xcb_grab_keyboard`s root and force-shows the bar (`BarHandlers.presentForPrompt`); `deactivate()` (:644) ungrabs and recomputes natural visibility. While active, `handlePromptKeypress` (:472) consumes keys before normal dispatch: Super+WM bind → prompt stays open (WM wins); `close_window` routed by cursor.
- **Editing model.** `EditorState` (prompt.zig:53) holds `buf` (256 cap), `len`, `cursor`, `mode` (`insert`/`normal`). Insert mode (self-insert/backspace/delete/arrows/Home/End/Return) via `insertChar` (:180); Ctrl keys through `handleCtrl` (readline set + Ctrl-C→deactivate). Editor handlers are function pointers in the global `handlers: Handlers` (:224) with bare-prompt defaults; the vim addon replaces them via `registerHandlers`.
- **Execution/history/completion.** Return → `spawnCommand` (:947): `histPrepend` + `histAppendToFile`, then fork→fork→setsid→`execvp("/bin/sh","-c",cmd)` with parent reaping the first child. History loads on first activation (`loadHistory` :930) from drun → bash → zsh → fish suffixes; `histLoadFile` reads a 256-KiB tail window, dedups via a Wyhash set, parses fish `- cmd:`/zsh `:ts;cmd`/`#` lines. Completions load once from `$PATH` + common dirs via `opendir` + `paths.exeInDir`, sorted then binary-searched; `updateGhost` (:752) prefers newest history whose command token exists, else the shortest matching executable, shown dimmed; Tab accepts.
- **Vim extension seam.** Strictly vim→prompt: vim.zig imports prompt's types and registers a `prompt.Addon{ .register, .init, .deinit }` (vim.zig:489); membership in `prompt_subs.addons` is build.zig file-presence generation (build.zig:835). prompt iterates `addons` in its own init/deinit; `register()` overwrites the handler pointers with vim's. The runtime switch `vimModeEnabled()` (prompt.zig:357) reads `config.bar.vim_mode` on every key — a runtime off-switch independent of the addon being compiled in. The mode pill renders only when vim handlers supply a non-empty label (`drawPill`, :1204).

**Implementation highlights.**
- prompt.zig: Segment binding (:1370-1386) with name, init/deinit, pollTimeoutMs (`blinkPollTimeoutMs`), onPollWakeup (`blinkTick`), draw, handleKeypress, consumeRedrawRequest, invalidateReloadCaches, overlay. # 28. `src/test/` — test organization + `helpers.zig` (AUXILIARY/soft core)

**Summary.** `src/test/` is the test-only subtree of the `hana` WM. It is a soft-core / auxiliary layer: every module here is test scaffolding for the production subsystems, none of it ships in the `hana` executable, and it is nice-to-have rather than load-bearing (deleting it changes nothing about runtime behavior). It is organized as a mirror of `src/` by category — `core/`, `config/`, `engine/`, `window/`, `bar/`, `input/` — plus two cross-cutting extras: `latency/` (benchmark-only) and two shared fixture modules. The two shared pieces are the real "payload" of this directory: `helpers.zig`, a headless fixture vocabulary (model/workspace construction, deterministic module-store resets, canonical geometry constants, and a recording/counting fake "X sink"), and `window/fixture.zig`, an X-gated integration fixture that boots the real `core → window → pipeline` wiring against a live (Xvfb) server and self-skips when none is reachable. Everything is driven by `zig build test` via per-file test roots auto-discovered by `build.zig`; there is no fake XCB wire layer and no mocked message pump — headless tests substitute a fake *sink* for the X request half, and X-dependent tests use a real display through an Xvfb wrapper.

**How it works (high-level).**
- **Directory ↔ subsystem mapping.** `src/test/core/` exercises `src/core/pure/` (bounded collections, workspace IDs, idmap) and `src/core/x11/masks.zig`. `src/test/config/` mirrors `src/config/`. `src/test/engine/` is the *conceptual* engine hub: it tests `src/core/architecture/model.zig`, the tiling layouts under `src/tiling/`, the reconcile/ledger in `src/core/x11/reconcile.zig`, the pipeline in `src/core/loop/pipeline.zig`, `src/core/proc/persist.zig`, and the `src/window/tracking.zig` facade — there is no `src/engine/` directory; the group name means "the state-machine/placement engine." `src/test/window/` mirrors `src/window/` (actions, focus, borders, wincache, workspaces). `src/test/bar/` mirrors `src/bar/`. `src/test/input/` mirrors `src/input/`. `src/test/latency/` has no production mirror — it is a test-only benchmark category.
- **Explicit gap: there is no `src/test/model/`.** Model tests live under `engine/` (`model_test.zig`), which is where they sit because they also exercise the tiling/minimize/fullscreen/workspaces behavior modules layered on the model.
- **The runner is `zig build test`.** `build.zig` auto-discovers every `*_test.zig` module under `src/` and creates one `zig build test` run per file (`build.zig:307-337`). Every test root links the full system library set and gets the same cross-wired named imports (`model`, `utils`, `sync`, …) production uses — standalone `zig test <file>` cannot resolve those imports, so all tests go through the build. A `test_gates` table (`build.zig:250-285`) maps each test file to a feature gate (`has_tiling`, `has_seg_clock`, etc.) and an `x_gated` flag. A discovered `*_test` module not in the table, or a stale table row, is a hard build error (`build.zig:296-323`), so the gate table can never silently stop running a test or run an ungated one.
- **X-gated tests serialize; unit tests run in parallel.** The build chains the `x_gated` run steps so server-global input-focus assertions cannot race across the parallel test processes (`build.zig:333-336`).
- **No real hardware in default runs.** The two X-heavy groups self-skip: `window/fixture.zig`'s `setUp` returns `null` (test passes silently) when `$DISPLAY` is unreachable or owned by a live WM, and `HANA_REQUIRE_X=1` flips that skip into a hard failure (`fixture.zig:72-94`). The repo wrapper `dev/scripts/xtest.sh` runs the suite under its own Xvfb with `HANA_REQUIRE_X=1` forced. The bar group avoids real hardware differently: brightness tests fabricate a sysfs `/class/backlight/` tree in a temp dir, and slider/systatus/clock/carousel/vim are pure state machines with injected clocks (no sleeps).
- **Determinism is a first-class concern.** `helpers.testReset` re-arms the process-global minimize/fullscreen stores so any test passes in any order (`helpers.zig:21-30`); golden geometry rects are *derived* from shared constants rather than magic literals (`helpers.zig:126-160`); latency/bench tests run only cheap smoke loops by default and full iterations + timing only under `-Dbench` (`build.zig:53-57`), because the Zig build runner flags any test stderr as a failure.

**Edges & contracts.**
- **How the suite is driven.** `zig build test` (ideally via `dev/scripts/xtest.sh zig build test` for the X-gated half). Workspace root is the repo root; each `*_test` module is a separate test root/process, so test files share nothing at runtime except the X server (hence the serialization of `x_gated` runs). Named imports resolve only through the build's cross-wired module discovery.
- **What it exercises.** Effectively every production module is touched: `core/pure/*`, `core/x11/*` (reconcile/ledger/sink, masks), `core/loop/*` + `core/proc/*` (pipeline, persist, lifecycle), `core/architecture/*` (model, contract), `tiling/` + layouts, `window/*` (actions, focus, borders, tracking, wincache) and `window/modules/*` (minimize, fullscreen, floating, workspaces), `config/*` (reader, parser, schema), `input/*` (keybinds, keysyms, masks), and `bar/*` (clock, carousel, prompt/vim, slider, systatus, brightness, visibility, native ALSA/Pulse backends).
- **What it does NOT need.** No fake XCB wire layer and no message-pump harness exist — headless tests substitute the `TestSink` fake sink for the X request emitters, and gap-free behavior tests call `model.register`/`actions.mapRequest`/fixtures directly. Default runs need no X server, no real device files, no audio hardware, no wall-clock sleeps, no network, and no host config (`config/fallback.toml` is only compiled in for the exe, not tests). X-gated runs need only an Xvfb + `HANA_REQUIRE_X` if the run must not silently skip.
- **Test-only namespaces.** Because module auto-discovery names every `.zig` file under `src/` by stem, `helpers`, `scratch`, and `fixture` become importable named modules; they are not `*_test` so they never get build steps themselves — they are pure imported scaffolding. Deleting `src/test/` entirely is safe for runtime: the exe never imports this subtree.
