# Structural evaluation of hana (2026-10-08)

194 Zig files (~10.7k prod lines + 62 test files). Five parallel subsystem surveys, all claims re-checked against the tree.

## 0. The one constraint that explains most of the weirdness

Before any recommendation: **every `.zig` file under `src/` becomes a globally-named module via its file *stem*** (build.zig auto-discovery; collisions are a hard build error; a reserved-name list exists). Consequences that dominate everything below:

- **File names are global API, not local labels.** `input_events.zig` exists because `events` is taken (self-documented). `contract_window.zig` exists because `window` is taken. A directory move does *not* change a module's name — `contract/window.zig` would still register as `window` and collide with `src/window/window.zig`.
- **Directories carry no namespace meaning** except the one machine-enforced convention: `<owner>/modules/` → generated `<owner>_modules` registry. Everything else (`protocol/`, `state/`, `grammar/`, `loop/`) is documentation-grade taxonomy with nothing checking it.
- Therefore: **renames are the expensive operation** (touch every `@import`), **moves are cheap but cosmetic**, and any naming scheme must fit the global stem space. This is the single biggest lever on the "deceptively intuitive" problem you named — the confusing names are often not mistakes, they're escape hatches from a flat namespace.

## 1. Your contract*.zig question, answered directly

**Recommendation: merge `contract_window.zig` + `contract_segment.zig` into `contract.zig`; reject the `contract/` directory idea; keep `seams.zig` where it is (optional rename).**

Reasoning, in order:

1. **The directory option is structurally blocked.** `contract/window.zig` and `contract/segment.zig` would register as modules `window`/`segment` — hard collisions with `src/window/window.zig` and `src/bar/segment.zig`. You'd have to keep the `contract_` prefixes anyway, so the directory buys nothing but a deeper path.
2. **The split's stated justification is already false.** The entry's header claims the siblings were split because they "share no imports with each other or with these sections" — but `contract_window.zig` imports `model`, which the entry also imports (`contract.zig:15`). The import-disjointness rationale does not hold. (The *seams.zig* split is different and load-bearing: it's what keeps the three contract files inside check-layers Rule 3's xcb body sweep — that one must stay.)
3. **Merging is safe and simplifies three things at once**: the check-layers Rule 3 file list (3 paths → 1), the re-export indirection (8 re-export lines + 2 header paragraphs disappear), and the reader's question "which contract file is X in?" (answer: the only one). Total merged size ~851 lines — large but coherent, and the comptime partition asserts already carry their own eval quota. All three files are xcb-free today, so Rule 3 coverage is unchanged.
4. **Keep `seams.zig`'s location** (it is Rule-3-load-bearing and imported by exactly 2 files: `bar.zig`, `prompt.zig`). Its *name* is the weakest part — it is not a "seam" (the word appears 129× across 53 files and has lost meaning), it's the X-typed contract half. ## 3. Foundational / construction evaluation — how the logic actually relates

1. **The composition root is genuinely clean.** `main.zig` never names the bar (boot goes through the generated `surfaces` table), the tiling engine is reached only through `tiling_seam`, and the reconciler is the single wire boundary. The hub-and-spoke claim in ARCHITECTURE.md is true where it matters.
2. **The facade/re-export pattern is pervasive and double-edged.** contract→siblings, actions hub (36 re-exports), window dispatch facade, prompt facade, config 11-symbol facade, bar surfaces table. It successfully keeps single import paths, but it also means one symbol has 2–3 spellings (`actions.providerOf` vs `window.providerOf` are aliases; `manage.zig` and `admission.zig` bypass the facade with raw `window_modules` loops — justified in comments, but three dispatch styles appear within 18 lines of `manage.zig`). A "which hub is authoritative?" rule written once and enforced by grep would pay for itself.
3. **The plugin system's invariants hold at the hard edges and leak at the soft ones.** Machine-enforced: registry uniqueness, at-most-one single-binder hooks, hook-classification partition, no sibling-module imports. Leaky: `floating.zig` imports `actions` (a two-way loop with `actions/geometry.zig` — module→action-layer dependency, inverse of the documented direction); the covering-query family (6 spellings) survives as wrapper pass-throughs (`window.isCoveringMode`, `actions.isCoveringOnWs`) even after the hooks were correctly folded into `model`.
4. **Wire policy is a second, orthogonal taxonomy.** check-layers' allowlist (who may send configure/map/focus outside reconcile) cuts *across* directory buckets — some bucket names (`window/protocol/`) accidentally encode this permission axis. Any directory rethink should keep this axis visible (the allowlist comments are among the best docs in the tree) rather than pretending buckets are pure abstraction.
5. **Purity enforcement has a real hole (verified by me just now):** `assertPureLayerImports` in build.zig is **dead code** — `source_root = "src/"` joined as `"{s}/{s}"` produces `src//config/...` paths that never match the `"src/config/"` prefix tests, and the model `endsWith` check fails on the doubled slash the same way. Additionally the config allowlist predates the grammar/source/reload split (lists only `parser, schema, types, fallback, keysyms`; config.zig now imports 7 more siblings that the written policy would reject). **Today, xcb-purity of config/tiling rests entirely on Rule 3's shell body sweep.** Fixing the path bug without extending the list would fail the build on config's own wiring — they must be fixed together.
6. **Vocabulary drift is the largest cumulative readability cost** (bigger than any single file): one concept five names (parked/minimize), four "reconcile"s in prose, "sync" surviving as a ghost word for reconcile, "seam" 129×/53 files, `ws` vs `workspaces`, `latency` vs `bench`. The KISS pass-2 devlog sweep removed *changelog* noise; this is *live-code* noise.
7. **Test blind spots and structural conflation are the same map.** Every >600-line file (state, drawing, window, parser, types, schema, focus, admission) has weak or zero direct coverage; every crisply-split area (input, tiling, pure/) is fully covered. That's not coincidence — conflation makes files untestable, and untested files accrete. Decomposition and test-backfill should be paired per file, not sequenced globally.
8. **Stale first-party docs**: ARCHITECTURE.md still says contract.zig "declares xcb event types" and is "outside the pure frontier" (false since the seams split — it's now Rule-3-swept as pure); `library/file-structure-concerns.md` references four files that no longer exist (`contract_x11`, `persist`, loop-`diag`, loop-`grabs`); pipeline.zig's "X-free" header is false; ledger has a dead import. The tree's doc-comment quality is otherwise exceptional — these are the rot spots.
