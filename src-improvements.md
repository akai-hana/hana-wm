# hana — `src/` design-review: cleaner/purer conceptual implementations

> One READ-ONLY design-review agent per section. Each agent follows four steps:
>
> 1. **Conceptual read** — read the section's analysis entry (+ legend) and form a high-level model of
>    how the code implements its concepts and what architectural themes it leans on.
> 2. **Design brainstorm** — *before* reading the per-file code, brainstorm conceptually/architecturally/
>    structurally cleaner and purer ways to implement the section so it is better at a high level.
> 3. **Grounding in code** — actually read the real source files composing the section, line-level.
> 4. **Second thoughts + final actions** — revise the brainstorm against reality; produce final,
>    concrete, actionable improvements with `file:line` references.
>
> Legend (hard/soft core, module, module extensor) as in the companion `src-analysis.md`.
> Reference doc: `src-analysis.md` (sections listed per entry below).

## 1. `src/main.zig` — composition root (HARD core)
**Conceptual model (step 1).** `main.zig` is a 194-line boot script whose entire job is to order ~15 subsystem initializers correctly and then hand the process to a single event loop; the ordering *is* the architecture (atom cache before DPI, XKB before keybinds, keybinds before config free, model before seeding, bar before restore). It also owns the process-global facts (X connection, allocator, config box, env hand-off) and is the only place that translates errors into exit, so it is simultaneously the composition root, the resource owner, and the boot-order oracle.

**Design brainstorm (step 2).**
- Split boot into typed phases ("pre-model" vs "post-model") so ordering mistakes are compile errors.
- Registry-driven lifecycle (a comptime `boot_sequence` of `{init, deinit}`) making LIFO teardown structural.
- RAII return values (owning `XSession`, a `ConfigBox` type) instead of return-triples + remembered defer rules.
- Single-source the cross-process env contract (`HANA_RESTORE`/`HANA_CONFIG_DIR`) into a typed `env.zig`.
- A testable root: `main()` → thin wrapper over `boot(BootInputs)` with injected session/allocator/env.
- Make restore a registered "action" instead of an env-string special case; comptime-resolve the optional surface lifecycle; give the root exactly one documented failure story.

**Grounding in code (step 3, second thoughts).**
- The ordering is real and prose-documented via load-bearing comments (main.zig:48-50, 62, 67-68, 71-73, 80-86, 92-93, 105, 107-110, 134-135); cross-cutting-audit.md:87 blesses it — I disagree with the conclusion, not the observation.
- **The `errdefer` at main.zig:64 is dead code on the success path and a double-free on every error path.** Nothing between it and the ownership transfer at main.zig:69 can fail; but it stays armed, and on error the `defer` (main.zig:88, freeing the box) runs *before* the earlier `errdefer` (main.zig:64, destroying the same pointer). Reachable via `signals.setup` (main.zig:98) and `window.init` (main.zig:102). On the reload branch the guard at main.zig:88 is false and the box is already freed at events.zig:382-383 — double free again. UB.
- `try events.run()` (main.zig:126) is a phantom error surface: events.run contains no `try`/`error` yet is `!void` → statically `anyerror`, so a future error inherits the double-free chain.
- main.zig:149-150 is the root's only `.after` reconcileGrabFocus (controllers use `.before`); `adoptRootWindows` passes `on_current=false` (window.zig:885) so main hand-copies the actions.zig:1013-1014 tail, coupled by comment (main.zig:145-147) and exercised only on re-exec (IMPROVEMENTS.md:264).
- `adoptRestoredSession` (main.zig:136-156) is the sole caller of persist.loadToGlobal / window.adoptRootWindows / actions.applyRestoredLevel — it drags `persist`+`focus` imports for one call each. Allocator policy duplicated (main.zig:46 vs :137, core.zig:54).
- The check-layers.sh:69 allowlist on main.zig is wrong-headed: its only two rule-1 hits are `xcb_flush` (main.zig:118) and `xcb_change_window_attributes` (main.zig:178) — the whole-file exemption would pass a future rogue `xcb_configure_window`.
- `connectToX`'s three error returns (main.zig:169/174/190) leak the connection (the disconnect defer at main.zig:44 registers after return); harmless at exit, but the "never disconnect an errored stream" rule lives at the call site.
- `surfaces` is comptime `null` when bar is absent (build.zig:466) — that's why main.zig:115-116 need `build_options` at all.
- Testability: the integration fixture hand-replays the boot (fixture.zig:186, 206-211), skips `seedParamsFromConfig`, and hand-seeds layout cycle at fixture.zig:215-221 — proven drift from prose-order boot.

**Final actionable improvements (step 4).**
1. **Delete the dead+harmful `errdefer` at main.zig:64.** Eliminates a guaranteed double-free of the config box on the `signals.setup`/`window.init` error paths. Risk: none. **Quick win; highest value in the file.**
2. **Make the config-box identity guard explicit** — let `core` own the box (e.g. `core.setConfig`/`core.deinitOwnedConfig`) so main's defer (main.zig:87-91) and reload (events.zig:382-383) use one ownership call. Risk: low. **Quick win.**
3. **Give `connectToX` an owning return type** (`XSession` with `deinit` encoding the has-error check), dropping the deferred disconnect at main.zig:44; closes the three leak paths. Risk: low. **Quick win.**
4. **Single-source the env hand-off** — typed `restart.restorePathFromEnv()` + config-dir accessor, consumed at main.zig:122; removes four hardcoded copies of two contract strings. Risk: low. **Quick win.**
5. **Move `adoptRestoredSession` out of the root** into `src/window/restore.zig`, and share the "focus after geometry" tail with actions.zig:1013-1014. Drops `persist`/`focus` imports from main; makes the re-exec-only path reviewable. Risk: low-medium (mind import edges). **Structural, small.**
6. **Put main's two raw XCB calls behind `core/x11/wire.zig`** (`wire.flush`, `wire.claimWmGrab`), then remove main from check-layers.sh:69. Shrinks the rule-1 hole at the entry point. Risk: low. **Structural, small, high architectural payoff.**
7. **Comptime-resolve the surface lifecycle** — emit a no-op `Surfaces` (full field list) in build.zig:461-466 instead of `null`, drop main.zig:16/115/116. Boot stops branching on a build flag. Risk: medium (contract.zig:76-79 documents the null design; four other sites share it). **Structural.**
8. **Fix the phantom error surface** — make `events.run` return `void` (events.zig:597), drop `try` at main.zig:126. Risk: none. **Quick win, pair with #1.**
9. **Extract a shared phase-split boot plan** for fixture reuse — but split at the signals line (signals.zig:183 installs process-wide handlers a test must not call); fixture already drifted. Risk: medium-high. **Structural; do last.**
10. **Centralize the allocator** — pass main.zig:46's `alloc` into `adoptRestoredSession` (main.zig:137) or read it from core. Risk: none. **Quick win.**

## 2. `src/core/` hub — `core.zig` + `events.zig` + `pipeline.zig` (HARD core)
**Conceptual model (step 1).** `core.State` is the process-wide heap of immutable-for-the-process facts (connection, screen, root, allocator, atomically-swapped config) plus monotone fact revisions; `events.run()` is the single driver (one blocking `poll` over the XCB socket and the signal self-pipe, with a bar-owned deadline); `pipeline.zig` is the reconcile choke point funneling every model→wire mutation through one server-grab bracket with exactly one flush.

**Design brainstorm (step 2).**
- Single blocking `poll` with a *core-computed reduced deadline* (min over timer-source hooks) beats N sub-loops and stops core knowing "bar" exists.
- Post-batch duties as an ordered *stage table*, making load-bearing orderings executable, not comment-enforced.
- The loop owns "what runs when", the pipeline owns "what a transition does", the contract owns "who may plug in"; "you must ungrab-and-flush" should become a token.
- Deadlines as a monotonic reduction with an explicit no-timer sentinel, not `i32 = -1`; a stall source must be a loud bug.
- A cheap reentrancy depth counter converts nested-entry aliasing bugs into an immediate panic.
- Split "loop state" / "session state" / "bootstrap state" lifetimes instead of mixing them in `core.State`.

**Grounding in code (step 3, second thoughts).**
- Loop really is a 2-fd blocking poll with a bar-only deadline (events.zig:602-605 fds, :614-618 `-1` default, :658-666 branches); signal-before-flags and reload-before-reexec orderings are real and commented (:637-638, :652-656).
- **Motion coalescing is the strongest engineering here and it is order-preserving** — shared comptime-parameterized drain (events.zig:429-462) with a `pending` carry-over slot, budget split by `with_tail` (:483-503), "dispatch the stashed non-motion now" rule (:547). My naive "simpler drain" would be strictly worse.
- Post-batch stages are hardcoded inline in comment-justified order: events.zig:576 (spawn drain), :578-579 (bar), :584 (focus settle, ordering prose at :580-583), :589-592 (border sweep gated on Facts snapshot at :514), :594 (flush). Best spot for a stage table.
- Dispatch table is tight (events.zig:115-140, guard :191, warn :167-171, RandR pre-route :177-183), but `& masks.synthetic_event_mask` at :185 and again in `isMotion` (:469) aliases any code ≥ 0x80 onto a core code — XKB's 85-101 range maps onto Motion/Button/KeyPress; documented hazard at :146-153, only `isRandrEvent` fixed.
- Pipeline enforces its bracket exactly once (pipeline.zig:177-182, `Grab` is a defer). Smells: `ctx()` is a global-overwrite builder (:91, :120-139) called twice per reconcile (:178 then :187); `preReconcileDuties` repeated at five sites (:186, :211, :265, :316, :326).
- **Grab/flush discipline leaks out of core:** bar opens its own bracket (bar.zig:1177) + flushless `reconcileNow` (bar.zig:1386, :1596) + its own `xcb_flush` (bar.zig:1236, :1516, :1539). Flush owners scattered across ≥8 non-core sites.
- core.zig is small and honest but carries **two** init latches (`core.isReady()` core.zig:119 vs `pipeline.initialized` :30), no `deinit`, and `dpi_info` (:146) deliberately outside `State` — a third lifetime category.
- Config reload already a textbook commit-point protocol (events.zig:289-388); re-exec correctly persists before dropping the connection.
- **The one real hole: the spawn pipe is never polled.** spawn exposes no fd accessor; `g_pending` entries (spawn.zig:132) drain only from events.zig:576 (needs an X batch) or SIGCHLD. A slow spawn with no X traffic stalls indefinitely on a no-bar build (`-1` deadline).

**Final actionable improvements (step 4).**
1. **Put the spawn pipe in the poll set** — `spawn.readFds()` beside `drainPendingSpawns` + a third `pollfd` (events.zig:602-605) with a dispatch arm beside :576. Removes the last unbounded-latency path. Risk: med (dynamic fd count). S–M.
2. **Refuse `-1` from `xcb_get_file_descriptor`** (events.zig:599): on a broken connection poll silently ignores it and, with `-1` timeout, blocks forever instead of taking the ERR/HUP break. **Quick win.**
3. **Stop aliasing codes ≥ 0x80 through the 0x7F mask** — after the RandR branch, `if (event_type >= 0x80) return;` in dispatch (events.zig:185) and the same guard in `isMotion` (:469). **Quick win.**
4. **Build the reconcile ctx once; funnel the pre-reconcile duty** — make `withServerGrab` pass its ctx to the body (kills the :178/:187 overwrite and the `grabCtx` clobber at :325-328), fold the five `preReconcileDuties()` calls into one `prepare()`. Risk: low. S.
5. **Encode post-batch stages as an ordered table** (events.zig:576-594): `const post_batch_stages = [_]struct{ fn() void }{...}` — order becomes data; new subsystems append rather than edit the loop. **Structural**, risk low.
6. **Replace the bar-only deadline with a core deadline reducer** — core owns `fn deadlineMs() ?i32` reducing over a `Timers` list; the bar contributes one entry. Pairs with #1. **Structural**, S–M.
7. **Unify grab+flush ownership; give the bar the same token** — export a `ScopedGrab` from pipeline; the flushless `reconcileNow` becomes pipeline-internal. Highest-value correctness item; risk med (bar is the trickiest client). M.
8. **Split the three lifetimes and collapse the two init latches** — one `core.Phase` enum queried by both core.zig:119 and pipeline.zig:30; keep bootstrap in `State`, move loop state into events.zig locals. Risk: low. M.
9. **Add a reentrancy depth guard to the pipeline** — `var depth` incremented in `withServerGrab`, `assert` on re-entry (X `GrabServer` is not reentrant-counted). **Quick win.**
10. **Hygiene cluster** — `events.run` `!void`→`void` (:597); pick one reporter for "no user config" (:306 vs :329-335/:653); `reload_in_progress` bool (events.zig:289); a zero-arg `reconcileGrab()` alias for the 17 `reconcileUnderGrabNow(.{})` sites in actions.zig. **Quick wins.**

## 3. `src/core/pure/contract.zig` — the open contracts (HARD core)
**Conceptual model (step 1).** contract.zig is the type-level boundary where optional subsystems bind: `Surfaces` (all-required fn-pointer set the bar satisfies), `WindowModule`/`Segment`/`Layout` (all-optional hook structs via `pub const module`), and the tiling interchange vocabulary (`View`/`List`/`Placement`/`HintsView`/`Env`). Absence is encoded via `null` hooks and build-generated registries that shrink to empty, so core dispatches through uniform loops without ever naming an optional module; capability flags (`self_ticking`, `center_slot`, `dirty_sources`) are the negotiation channel; registry order (sorted-stem scan) is priority.

**Design brainstorm (step 2).**
- "Required fn-ptr set" (`Surfaces`) and "optional hook structs" are opposite encodings of the same host↔addon relation — conceptually one relationship type with two directions.
- The untyped `*anyopaque` seam loses type safety at 6+ signatures; the load-bearing constraint is only "contract must not import the orchestrator" — the *vocabulary* could live in a shared pure module both sides import, giving typed pointers.
- Capabilities as a comptime `Cap` enum instead of string names → typo'd names become compile errors; modules could *declare* host requirements.
- Registry invariants should be *derived from the contract type*, not emitted as string-matching comptime in build.zig.
- Versioning: a contract-level id would make the persisted blob self-describing instead of ordinal-relative.
- Four coexisting optionality idioms (`null` fns, `has_*` flags, empty-registry, whole-Surfaces-null) — the *type* should answer presence.
- The dispatch family has 4 shapes, none fallible; a `callAllTry` would give error policy one owner.

**Grounding in code (step 3, second thoughts).**
- The "no import edge" claim is **half-true**: contract.zig:48-49 imports the generated `tiling_modules` and re-exports it, contradicting contract.zig:282-284 and ARCHITECTURE.md:114 — the *doc* is the defect.
- contract.zig sits in `src/core/pure/` yet imports `core` (:38) and `xcb` (:39), exempted from both guards (build.zig:1608, check-layers.sh:191); ARCHITECTURE.md:42 calls `pure/` "X-free vocabulary". The highest-fanout file is the only unguarded one.
- `single_binder_hooks` (contract.zig:260-270) is 27 hand-written string names vs 36 struct fields; build.zig:1072's `if (!@hasField(T, hook)) continue;` silently disables a hook's invariant on typo, and `Segment`'s "at most one" claims (`measureString` :433, `overlay` :479, `naturalWidth` :437) are unenforced.
- `providerOf` iterates by value (contract.zig:289-290) — a 36-field struct copy every lookup, in hot paths (window.zig:931,1042; actions.zig:39,226,272,335,520).
- **`Layout.compute`'s "exactly one placement per window" is enforced nowhere:** `BoundedList.append` returns bool on overflow which a `void` compute cannot report; neither tiling.zig:308-312 nor sync.zig:312 validates count/identity/order.
- The opaque seam is real: `Segment.onClick` (contract.zig:443-450) packs two unnamed bools + ctx + two fn pointers into 6 positional args.
- `Env.variant_idx` (contract.zig:584) duplicates `View.params.variant_idx` (:537); sole producer pipeline.zig:112 — one fact, two carriers.
- Pointer/value inconsistency: `View.params: *const` (:537) vs `preReconcile(model.LayoutParams)` by value (:522); `View.hints: *const HintsView` (:539) points at a stack local (sync.zig:305-307).

**Final actionable improvements (step 4).**
1. **Enforce the layout output contract** — post-condition at tiling.zig:308-312: `assert(out.len == v.order.len)` + per-index win match. Turns a silently mangled desktop into a debug failure. Risk: may surface a latent module bug (run suite first). **Structural-lite.**
2. **Make hook classification exhaustive/typo-proof** — in build.zig:1068-1080, assert every fn-pointer field is named in `single_binder_hooks` **or** a new `multi_binder_hooks`; an unknown name → `@compileError`, not `continue`. **Quick win.**
3. **Per-contract binder lists** via `@hasDecl(T, ...)` (replacing hardcoded contract at build.zig:1068), adding Segment's `measureString`/`overlay`/`naturalWidth`; makes the "at most one" claims real. **Quick win.**
4. **`providerOf` returns `?*const T`** (contract.zig:285-292) — removes a 36-field struct copy per dispatch. **Quick win**, low risk.
5. **Type the capability lookup** — segment.zig:325-336 takes `comptime std.meta.FieldEnum(contract.Segment)` (as bar.zig:176 already does), updating bar.zig:70-71. **Quick win.**
6. **Drop `Env.variant_idx`** (contract.zig:584; producer pipeline.zig:112) — `View.params.variant_idx` already carries it. **Quick win.**
7. **Fold the `has_bar` gate into the `Surfaces` type** — emit `pub const Surfaces: ?contract.Surfaces = if (has_bar) @import("bar").surfaces else null` (build.zig:466); convert ~20 sites. Reduces (not eliminates) optionality idioms; screen.zig:33 still needs the flag. **Structural.**
8. **Unify fallible lifecycle dispatch** — add `callAllTry`; route bar.zig:1248/1256 + window.zig:270/287 through it. **Quick win.**
9. **Replace the `onClick` 6-arg tuple** (contract.zig:443-450, bar.zig:317-318) with a named `ClickCtx` struct. **Structural.**
10. **Give contract.zig a real purity story** — splitting `Surfaces` (its only xcb reason, bar-specific) into a `contract_x11.zig` lets contract satisfy ARCHITECTURE.md:42 and enter check-layers Rule 3. **Structural.**
11. **Stable module identity** — add `id`/`name` to `WindowModule`, stamp instead of `@intCast(idx)` (persist.zig:188). **Structural.**
12. **Doc fix** — contract.zig:282-284 (and src-analysis.md:70) claim no generated-registry import edge; :48-49 has one and it is intentional. **Quick win.**

## 4. `src/core/runtime/` session & lifecycle — `persist.zig` + `restart.zig` + `signals.zig` + `spawn.zig` (HARD core)
**Conceptual model (step 1).** hana's "session" is not a struct — it is a *file plus an execve*: `persist.zig` projects the model into a flat, versioned, atomically-renamed JSON shadow record set; `restart.zig` turns a flag (keybind or SIGUSR1) into an in-place `execv` of `/proc/self/exe`; `signals.zig` is the async→sync bridge (atomic bitmap + self-pipe wake token dispatched on the event loop); `spawn.zig` runs user commands as detached double-forks whose outcome returns over one pipe so the WM can route the resulting window by pid. Hand-off channels: the on-disk file (state) and the environment (`HANA_RESTORE` restart.zig:122, `HANA_CONFIG_DIR` events.zig:415-416, read at main.zig:122).

**Design brainstorm (step 2).**
- Typed shadow struct + `std.json` + version-as-top-level-field is right; per-feature tagged blobs already, but *durability* (fsync-before-rename) is missing for the power-loss claim.
- Per-instance path (not per-uid) for the restore file — two hana instances share the default name.
- Reload vs re-exec is the correct two-tier, but the loop should consume them as one ordered "requests this tick" queue.
- Ideal signal bridge is `signalfd`; the self-pipe+bitmap is the portable fallback. Once state lives in the bitmap, the byte payload and in-handler drain loop are vestigial.
- Double-fork+pipe is honest (`_NET_WM_PID` is the grandchild's); cleaner alternative is `PR_SET_CHILD_SUBREAPER` + single fork — loses exec-failure detection and re-parents grandchildren to hana.
- Ownership: the protocol is split across persist/restart/events.handleReexec/main.adoptRestoredSession; a single `Session`/`Handoff` value would make ordering auditable.

**Grounding in code (step 3, second thoughts).**
- Most brainstorming ideals are *already implemented*: bitmap-not-bytes (signals.zig:36,41), sigaltstack-before-ONSTACK (:214-225), O_EXCL/no-follow temp (persist.zig:246-261), drain-before-consume ordering (events.zig:630-638).
- **The byte is entirely vestigial:** drainAndDispatch discards the buffer and dispatches only from the bitmap (signals.zig:274-284); the write at signals.zig:42-43 is never read; the in-handler drain-retry loop (:54-64) is unnecessary (EAGAIN ⇒ already readable).
- **Real bug 1 (zombie leak).** drainPendingSpawns does `waitpid(pid, null, WNOHANG)` then *unconditionally* sets `entry.pid = -1` (spawn.zig:225-228) — but EOF (fd close, spawn.zig:86) precedes `std.process.exit` (:87); if the loop wins the race `waitpid` returns 0 and nothing ever reaps it (reapPendingChildren only walks `g_pending`, :281-284).
- **Real bug 2 (async-signal-safety).** `log.err("Second fork failed")` (spawn.zig:65) runs in the child and takes the std.log lock — deadlockable if cairo/fontconfig held it. Everything else in the fork path is correctly raw (:36-41).
- **Real bug 3 (temp-name collision).** Temp is a fixed sibling `"{path}.tmp"` (persist.zig:244). Two instances: B's O_EXCL fails, B deletes A's in-flight temp (:255), B renames, A's rename fails ENOENT → propagates out of persist.save → **aborts A's re-exec** (events.zig:409→:656).
- **Silent failure channel.** finishSpawn computes `failed` and discards it (spawn.zig:245-274); no command string stored, nothing reported. No deadline on `max_pending_spawns=16` (spawn.zig:92): 16 wedged pipes permanently disable `exec` (:151-154).
- `variant_idx` restored unvalidated while `kind` gets a validated fallback (persist.zig:378 vs :384-393); success path can still install a past-end index after a binary change.
- **Stale restore file:** nothing unlinks it on clean exit; atomicWrite never fsyncs (persist.zig:262-266) despite the crash-mid-save claim (:239-241).
- `Snapshot.workspaces` is `undefined` (persist.zig:134) yet copied whole (:228) — correctness depends on the fill loop (:206-216) always completing.
- Doc drift: ARCHITECTURE.md:184 says "Signalfd-based" (it's a self-pipe); simplification-audit.md:63-66 flags a dead param that is already gone (restart.zig:60). Latent trap: `@intCast(@intFromEnum(signo))` (:40) panics in signal context for `signo ≥ 64`.

**Final actionable improvements (step 4).**
1. **Pid-qualify the temp name** — `"{s}.{d}.tmp"` (persist.zig:244). Kills the cross-instance delete race that aborts re-exec; lets the O_EXCL retry ladder collapse to a plain reject. Risk: none. **Quick win.**
2. **Only clear `entry.pid` when `waitpid` actually reaped** (spawn.zig:225-228), plus a `waitpid(-1, WNOHANG)` sweep in `reapPendingChildren`. No leaked zombies, one reaper path. **Quick win.**
3. **Remove `log.err` from the forked child** (spawn.zig:65) — raw `write(2)` or drop. Restores the fork-safety invariant. **Quick win.**
4. **Report failed spawns** — store a truncated command in `PendingSpawn`, `log.warn` when `failed` is set (:269). **Quick win.**
5. **Simplify the self-pipe to a single constant wake token** — delete the per-signo byte write (:42-43) and the in-handler read drain (:58-62); bitmap alone carries state. **Quick win.**
6. **Unlink the restore file on graceful exit** — `deleteFileAbsolute` next to "Shutting down gracefully" (main.zig:127) using the `HANA_RESTORE` path. Prevents adopting XIDs the server recycled. **Quick win.**
7. **`fsync` before rename (or downgrade the claim)** — one `file.sync(io)` before `renameAbsolute`. **Quick win / doc-only.**
8. **Add a monotonic deadline to `PendingSpawn`** — drop entries older than a few seconds in drain; 16 stuck pipes can't wedge `exec` forever. **Small feature.**
9. **Validate `variant_idx` on restore** mirroring `kind` (persist.zig:376-393) — clamp to `contract`-reported `variant_count` + warn. **Quick win.**
10. **Assert snapshot completeness** — `assert(snap.ws_filled == MAX_WS)` before the whole-array copy (persist.zig:134/:228). **Quick win.**
11. **Give the hand-off one owner** — a `Handoff { self_path, restore_path, config_snapshot }` built by one `restart.prepare()`, consumed by both ends; reload-before-reexec and save-before-disconnect become one auditable function. Risk: medium, no behavior change. **Structural.**
12. **Reconsider double-fork → subreaper** — `PR_SET_CHILD_SUBREAPER` + single `fork`+`setsid`: deletes the tag protocol, `PendingSpawn.buf/len`, finishSpawn's parser, ~80 lines and one fork per spawn. Risk: medium-high (grandchildren become hana's; exec-failure reporting lost). **Structural; not urgent.**
13. **Doc + micro fix** — ARCHITECTURE.md:184 self-pipe; retire audit.md:63-66; guard the shift at signals.zig:40 against `signo ≥ 64`; drop the redundant `mustDupeZ(self_path)` (restart.zig:119, `exec_path_z` already `[:0]const u8`). **Docs.**

## 5. `src/core/x11/` — synchronization boundary & raw X11 wire (HARD core)
**Conceptual model (step 1).** The boundary is a write-only *sent ledger* (what we last told X) diffed against an unconditionally recomputed *desire* (what the model+layout say now); the delta is emitted through an 11-slot `Sink` vtable into shims that are the only sanctioned place to touch libxcb, batched under one server grab and delivered by a single flush. `wire.zig` owns raw primitives/atoms/EWMH advertisement, `xcb.zig` is the single `@cImport` hub, `masks.zig` keeps cheaply-reproducible X constants out of the pure layers.

**Design brainstorm (step 2).**
- Effect list vs fused loop: planning `[]Effect` then applying is the textbook pure/replayable/testable answer; cost is a staging buffer plus a second pass.
- Sink altitude: the seam should carry *intent* (`apply(win, {rect?, bw?, stack?})`), not X request shapes; the merge decision belongs in the encoder, not sync.
- Ledger anchoring: attach last-sent state to the model entry rather than a parallel id-keyed store.
- Transaction shape: one grab bracket, one flush, defined once.
- Error recovery: cookies are weak; invalidating the ledger on the error stream is stronger.
- Drift repair: unconditional compute repairs client-mutated geometry only if reconcile reaches the window.

**Grounding in code (step 3, second thoughts).**
- **No effect list; a fused loop** — sync.zig:346-426 computes `computeDesire` (:512) and sends in the same iteration; the loop keeps read-before-write local (:359-360, :423-425) but all 10 sync tests need the recorder sink (helpers.zig:180-240).

*(Path note: the analysis doc's `src/model/model.zig` has moved; the live file is `src/core/pure/model.zig`.)*

**Conceptual model (step 1).** The model is the xcb-free single source of truth for all management state: a sorted, allocation-free `Store` of per-window `Entry` records, a fixed `[max_workspaces]WsState` array of per-workspace tiled order / focus MRU / layout params, and three globals (`current`, `focused`, `all_view_active`). ## 13. `src/tiling/tiling.zig` — the tiling engine (SUB-SYSTEM CORE, soft core)
**Conceptual model (step 1).** `tiling.zig` is a registry-agnostic driver: the model holds a bare `u8` layout index, the build-generated `tiling_mods` table is the only name→index authority, and `compute` is a three-line adapter handing a borrowed `View` to a layout's `compute` hook and collecting `Placement`s. ## 18. `src/input/input.zig` — the input sub-system (SUB-SYSTEM CORE, hard core)

## 19. `src/input/` keybind/XKB support — `keybind.zig` + `keysyms.zig` + `xkbcommon.zig` (SUB-SYSTEM CORE, hard core)
**Conceptual model (step 1).** This triad is hana's *translation seam* between the declarative world (a config file that names keys as strings) and the physical world (a keymap that names keys as keycodes). It is deliberately split into three one-direction steps so no layer needs both: `keysyms.zig` is a static, xcb-free name↔keysym vocabulary consulted only at config-load time (`config.zig:1150`); `xkbcommon.zig` owns the only live-device state, flattening the keymap into a 1 KiB inline `keycode → level-0 keysym` table (`xkbcommon.zig:87`, `:100`) so dispatch never consults lock-sensitive XKB state; `keybind.zig` joins the two ends by turning each config binding into a keycode for grabbing and a `(mods, keysym)` hash key for dispatch (`keybind.zig:24`, `:30`, `:70`). Its role is to be the *only* place where keysym-space and keycode-space meet, which is what keeps the config layer provably X-free (enforced by `build.zig`'s layer-purity assertion) and what lets a config reload rebuild bindings without ever touching XKB state.

**Design brainstorm (step 2).**
- **Make the keysym↔keycode boundary a value, not a mutation.** The keycode of a binding is *derived* from (live keymap, binding set) — a function of two volatile inputs — yet it is stored as a mutable field on the config's own data. A purer shape: the input layer owns an immutable `[]const CompiledBinding{ keycode, mods, action }` produced in one pass, and config keeps only declarative data. This deletes an entire class of "stale derived field" bugs and makes the reload ordering contract expressible as data flow rather than as a comment.
- **Give the resolver a representation that is honest about size.** Mods are masked to 4 bits before matching, and real configs hold tens of bindings, not millions. A sorted `[]const Entry` (or a 16×small direct-mapped table keyed by the masked mods) beats a hash map on every axis that matters here: no allocator inside the struct, no clear/retain lifecycle, duplicate detection becomes an adjacent compare, and the hot path becomes a branch-predictable binary search. "O(1)" is not the property worth buying here; zero-allocation and inspectability are.
- **Build both directions of the index in one pass, and make the reverse direction lossless.** A keysym→keycode *multimap* (a 256-bit keycode mask per binding, or a small inverted list) fixes two real losses at once: the current reverse lookup returns only the first matching keycode, and the forward table keeps only `syms[0]` of each level. It also turns the O(bindings × 248) resolve scan into a constant.
- **Two-phase validation with typed results.** Name validity is decidable at parse time (and already is — `config.zig:1156` rejects `NoSymbol`); keysym-bindability is only decidable with a live keymap, and is currently reported as a side-effecting `log.warn` during a mutation pass. A `ResolveReport{ unknown_name, unbindable, shadowed }` value returned by the build step would let the config layer surface "3 of your 40 binds can't fire" once, and let a test assert the policy.
- **Express keyboard readiness as state, not as a sleep loop.** The three retry probes plus a 40-symbol health heuristic encode a "the keyboard may not be there yet" assumption. An explicit `uninitialized → probing → ready → degraded` state, queried by the input layer, lets hana boot keybind-less instead of hard-failing at `main.zig:56`, and makes the heuristic a policy constant rather than a magic number buried in a walk.
- **Split the file by X-dependence, not by topic.** `xkbcommon.zig` currently holds X11 extension negotiation and per-client-flag policy, an X-free keymap→table transform, a readiness heuristic, and raw `nanosleep` plumbing. Only the middle piece belongs with the keysym vocabulary; the first belongs with X11 wire policy.
- **Own the C bindings once.** Two separate `@cImport`s of `xkbcommon.h` in one sub-system duplicate every declaration and can drift.

**Grounding in code (step 3, second thoughts).**
- **Confirmed — the write-back inversion is real.** `resolveKeycodes` mutates the caller's slice: `kb.keycode = state.keysymToKeycode(kb.keysym)` (`keybind.zig:72`) is called with `cs.config.keybindings.items` (`input.zig:66`, `input.zig:90`), and that derived field is then the *only* thing the grab path reads (`events.zig:216`). ## 21. `src/bar/` segment core — `segment.zig` + `segdraw.zig` + `metrics.zig` + `visibility.zig` (SUB-SYSTEM CORE, soft core)

The contract is a three-part loop: **measure** (`naturalWidth` → row reservation), **draw** (bar pins `ctx.width`, segment returns advanced x), **invalidate** (module drops its own cached width). Layout arithmetic, X wire, and applying a visibility decision are all `bar.zig`'s.

**Design brainstorm (step 2).**
- **Split `segment.zig` by concern**: draw vocabulary (`DrawCtx`/`Frame`/`castDraw`/`BarHandlers`) vs the title's pure geometry kernel vs comptime registry queries (`idByName`, `findAllByCapability`). Today three unrelated responsibilities share one file, and the largest coherent one (the title kernel) has no business being in the "shared vocabulary".
- **Unify the measure seam.** `draw` receives `*DrawCtx`; `naturalWidth` receives a *different* `*anyopaque` that is sometimes `&Frame` and sometimes `&FrameState`, re-interpreted back per-module. One read-only `SegQuery` (frame + reservation inputs) handed to both hooks would make the type explicit and delete every per-module reinterpret cast.
- **Return layout results instead of caching them.** A small `Painted { end_x, width, needs_relayout }` return would let the orchestrator own reservation bookkeeping uniformly, instead of every segment re-implementing "track the actual painted width and mark dirty when it changes".
- **Separate segment state from render material.** The width cache is a *side effect* of drawing; it deserves a first-class `Slot` value (width, optional key, redraw flag) the bar holds, so width bookkeeping becomes testable and no longer rides along inside a draw call.
- **Make `metrics` a struct.** Font size and bar height are derived together and re-derived together — including a hand-rolled save/restore on the reload failure path — yet the module owns a single `u16` behind a getter/setter pair. A `Metrics` value derived purely from (config, screen, font probe) and stored on bar `State` matches the file's name.
- **Shape visibility as a decision over an explicit state record**, not three positional booleans threading a live global model through a file that advertises purity. An enum decision carrying a *reason* makes the glue a single switch and the "why" testable.
- **Collapse the three observed slot behaviours** (fixed / keyed / collapsing) into one comptime mode instead of a `with_collapse` bool plus a separate `keyedWidthState` type.

**Grounding in code (step 3, second thoughts).**

## 22. `src/bar/drawing.zig` — the cairo/pango renderer (SUB-SYSTEM CORE, soft core)
**Conceptual model (step 1).** drawing.zig is the bar's only paint substrate and the only place cairo/pango/GLib symbols are named. It owns three things stacked in one struct: an off-screen X pixmap + cairo surface + context (the present path, blitted back with `xcb_copy_area`), a font/shaping state (one shared `PangoLayout` plus derived sized descriptors), and a small set of primitives that segments call with `(x, y, text, color)` — baseline-anchored text, ellipsized text, marquee-scrolled text, absolutely-sized indicator glyphs, straight-alpha rectangle fills, and width measurement. Everything above it — bar.zig's layout walk, segdraw's width bookkeeping, six segment modules — is pure arithmetic that eventually funnels into these calls; the renderer knows nothing about segments, config section names, or dirty state, and it never returns a cursor: callers pass `x` and consume the returned advanced `x`. Config is the only styling input, and the bar's uniform repaint idiom is `clearRegion` (bar.zig:650) → segment `draw` → `queueBlit` (drawing.zig:700).

**Design brainstorm (step 2).**
- **Split "what to paint" from "with what".** Every primitive today mixes geometry decisions (measure, ellipsize, split, fit, wrap) with canvas mutation (cairo source, Pango attrs, GC color). A purer shape is a value-level `Paint` command list built from `(config, box)` and executed by a `Painter`; then measurement and painting are the same pass by construction and the whole thing is testable without an X connection.
- **Layer text above fill.** A `TextRun` (bytes, font, style, width, ellipsize) value plus a `fillFraction`/gauge primitive above a dumb `fillRect` would let two-tone strings and meters be expressed declaratively, and would let the renderer own the "rect fills bypass cairo for straight alpha" policy (drawing.zig:484) as one named decision instead of an inline branch.
- **Detach the surface from the type engine.** The present path (pixmap/surface/ctx/gc/copy_gc) and the font book (descriptions, sizes, metrics) are unrelated lifetimes welded into `DrawContext` (drawing.zig:338). Splitting them would make font reload a first-class `setFonts` with one invalidation point instead of a pointer-identity cache, and let metrics be probed without duplicating surface bootstrap.
- **Kill the mutable-shared-layout discipline.** One `PangoLayout` mutated by `set_text`/`set_width`/`set_ellipsize`/`set_attributes`/`set_font_description` means correctness rests on remembering `applyStyleProps`/`restoreStyleProps` pairing (drawing.zig:643, 651). A layout owned per run (or a small pool) makes the pairing structural instead of conventional.
- **No image/icon concept exists and none is needed.** Icons are Pango glyphs; the only raster surface in the file is the 1×1 probe (drawing.zig:48, 839). A `FontBook` with a size→description map is the whole asset story.
- **Make the error surface honest.** Measurement is infallible and total; text draws declare `!void` with no error site; font paths genuinely fail; X writes fail silently. Four different policies for four layers of one call tree.

**Grounding in code (step 3, second thoughts).**
- **Confirmed: font state is welded to the surface, and it leaks.** The `sized_font_base` pointer-identity key (drawing.zig:366, 521, 530) defends against an in-place font reload — but `loadFonts` is only reachable via `loadBarFonts` (drawing.zig:880), whose sole caller builds a brand-new `DrawContext` (win.zig:184). The invariant is currently unreachable complexity. Meanwhile `probeFontMetrics` builds a local `FontState` (drawing.zig:847) and never calls its own `deinit` (drawing.zig:215), leaking one `PangoFontDescription` per probe — and `resolvePercentageFontSize` probes on every reload (bar.zig:204 → 193). I also under-counted the coupling: prompt.zig:1107 reaches into `dc.font.getMetrics()` and re-derives baseline math, so the "private" font state is already public API.
- **Confirmed and worse than expected: two-tone segments split the shaped string.** `drawPaddedSegmentValue` validates the value by raw pointer arithmetic (drawing.zig:797), then re-shapes the string in up to three pieces and advances by summing per-part measurements (drawing.zig:814). The background width comes from the whole string (drawing.zig:809), so the drawn ink and the reserved box can disagree wherever shaping is not slice-additive (kerning across the split, combining marks, ZWJ emoji). A Pango foreground attribute over the already-computed byte range (drawing.zig:813) removes the validation hack, the loop, and the drift at once.
- **Confirmed: a cross-transport paint-order invariant is real, undocumented, and unenforced.** `fillRect` writes through XCB immediately (drawing.zig:504) while cairo buffers until `cairo_surface_flush` in `blitImpl` (drawing.zig:681) — so every XCB fill in a frame lands before every cairo glyph in that frame. All current call sites happen to be fill-then-text (drawing.zig:737, tags.zig:140, slider.zig:400), so nothing is broken today, but nothing states the rule and one text-then-occlude case would render inverted.
- **Refuted: gauges are not in this file.** The only gauge is the slider drag bar, composed by hand in slider.zig:397 from two `fillRect`s plus a percentage `drawText` — and it borrows `title_minimized_accent` (slider.zig:406), another module's color key, as its fill color. That is a real style-leak, but the fix belongs in a widget layer or a new config key, not in a "gauge drawing" section here.
- **Refuted: the phantom error union is worse than "vestigial".** `drawTextImpl` (drawing.zig:606) has no error site, yet `drawText`/`drawTextEllipsis`/`drawTextStyled` return `!void` and the `try` ripples into title.zig:227, prompt.zig:1025, tags.zig:144 — and slider.zig:411 swallows an impossible error with `catch {}`. Meanwhile `measureTextWidth` is infallible *and* mutates the shared layout (drawing.zig:629, 468), which `paintedSegment` silently depends on (drawing.zig:735).
- **Refuted (a good call I nearly flagged as a bug): the `last_color` cache is safe across `cairo_save`.** `drawTextScrolled` colors before saving (drawing.zig:575 then 577), so the restore returns to the just-set source; no desync. Same for the dead `copy_gc == 0` guard (drawing.zig:682) — merely dead, not wrong.

**Final actionable improvements (step 4).**
1. **Two-tone segments as one Pango attribute pass** — replace drawing.zig:797-826 with a `PangoAttrForeground` over the `[start, start+len)` range already computed at drawing.zig:813, painted via `drawTextImpl`. *Why:* removes the pointer-arithmetic subslice contract, the three-way re-shape, and the measure/paint width divergence; gains ellipsize+style composition for free. *Risk:* low-med (new attr binding; width is unaffected by color so the measure path is unchanged).
2. **Free the probe's `FontState`** — add the missing `deinit` at drawing.zig:847. *Why:* confirmed leak of one font description per `resolvePercentageFontSize` probe (bar.zig:204). *Risk:* none.
3. **Return an owned `SizedFontList` value** — collapse buildSizedFontList/freeSizedFontList (drawing.zig:855, 871) into one struct whose `deinit` frees what it allocated. *Why:* `freeSizedFontList` re-reads `core.getState().config.bar.fonts.items` (drawing.zig:872) to infer ownership by pointer identity; a config swap between build and free mis-frees. *Risk:* low (two call sites: bar.zig:195, drawing.zig:882).
4. **Fix the error surface** — drop `!void` from drawing.zig:559, 592, 665 (or give `drawTextImpl` the one real failure it can have) and let the truly fallible font path stay `!`. *Why:* removes a fake error path threaded through five modules and a `catch {}` on an impossible error (slider.zig:411). *Risk:* low, caller-visible churn at ~8 `try` sites.
5. **State and enforce the paint-order rule** — document at `fillRect` (drawing.zig:484) that XCB fills are ordered before all cairo glyphs of a frame, and make it non-load-bearing by flushing cairo before the first XCB write of a frame (drawing.zig:680). *Why:* the invariant is currently a coincidence of call-site ordering across six modules. *Risk:* low for the comment, low-med for the flush.
6. **Split `DrawContext` into `Surface` + `FontBook` + `Painter` facade** — drawing.zig:338-460. *Why:* deletes the pointer-identity sized-font cache (drawing.zig:366, 521) and the duplicated layout bootstrap in the probe (drawing.zig:839-845), and stops leaking `dc.font` into modules (prompt.zig:1107). *Risk:* med (mechanical, ~8 call-site files).
7. **Per-run text state instead of the shared mutated layout** — make `TextRun` a value and give the run its own layout, retiring the apply/restore pairing (drawing.zig:643, 651) and the measure-as-side-effect trick (drawing.zig:735). *Why:* a forgotten restore today silently corrupts every later draw in the frame. *Risk:* med.
8. **Own the gauge style** — add a `fillFraction` primitive (or a `widgets.zig` above the renderer) and stop slider.zig:406 from borrowing `title_minimized_accent` for the volume/brightness fill. *Why:* gauge geometry (pad/inner/percent) is re-derived per module and its color has no config key. *Risk:* low-med.

## 23. `src/bar/modules/` — MODULES: `clock.zig` + `tags.zig` + `layout/` + `variants.zig`
**Conceptual model (step 1).** These four files are the bar's self-contained segment families, and conceptually they are all one thing: **resolve a small piece of live state into a short piece of text, paint it into a reserved row slot, and act on a click.** `clock` (self-ticking) resolves wall time; `tags` (registered as `"workspaces"`) resolves N workspace cells; `layout` resolves the active tiling layout's icon glyph; `variants` resolves the active variant's indicator glyph. Three of the four are ~40-line files whose entire body is a metadata lookup plus one `segdraw` binding; `tags` is the only genuinely stateful renderer, owning a per-workspace measurement/geometry cache and per-cell click routing. None imports another, and none names a sibling: `layout`/`variants` reach the tiling world only through the generated `contract.tiling_mods` plus the pure `contract.activeLayoutKind` gate, and `tags` reaches the WM only through `DrawCtx.frame`.

**Design brainstorm (step 2).**
- **A purer MODULE contract is text-first, not draw-first.** All four are `resolve → text → padded draw → width store → click` — a `resolve` shape, not a `draw(dc, config, height, x)` shape. A `segdraw.textModule(name, resolve, opts)` would make `layout`/`variants` literally three-line files, would give the row a *single* definition of "how wide am I", and would let the plugin template (`dev/plugin-template/segment.zig`) teach one contract instead of today's `draw + optional width bookkeeping + optional click` trio.
- **Width should be measured from state, not reported after painting.** Today the reservation is a *report of the previous frame* — `store` is called from inside `draw` — and the `redraw_pending` fold exists mainly to paper over the resulting one-frame skew. If `naturalWidth` were uniformly "measure from the frame", the skew disappears, `widthState` degenerates into a measurement memo, and `with_collapse` becomes unnecessary.
- **The `widthState` / `keyedWidthState` split is a generality leak that belongs in the segment API.** Two primitives exist only because the clock keys its reservation on a display mode and nothing else does. One "measure-and-memo with an optional key" primitive pushed down into the bar's segment vocabulary would cover clock, tags and the icon modules uniformly, leaving each module to own only *what its key is*.
- **Per-module state is a file-scope `var` smuggled through a type factory.** `widthState(tag)` returns a struct whose state is a mutable `var` inside the returned type, keyed by a comptime tag string. A purer home is an explicit per-segment `Instance` the bar passes as the `*anyopaque` context: state becomes inspectable, testable without global mutation, and correct if a second bar ever exists. The bar already passes two *different* payloads through that same `*anyopaque` (`&DrawCtx` to `draw`, `&Frame` to `naturalWidth`), so the polymorphism is already ad hoc.
- **The layout-metadata lookup should be one seam, not two.** `layout` and `variants` each re-implement "resolve active kind → index `tiling_mods` → read bar metadata", each with its own fallback spelling (`"><>"` vs `""`). One contract-level "active layout's bar metadata" accessor halves both files and turns "the registry may not have an answer" into one documented decision. Relatedly, the *variant index* is read by hand-walking the model while `getCurrentLayout` does the identical walk for `kind`; that walk belongs beside `getCurrentLayout`, not inside a bar module.
- **tags is conceptually a *list* segment, and the list contract already exists in the tree.** It has N cells with per-cell styling, click target and glyph offset; `segmod.segmentIndexOfX` already does exactly the "which cell is under this pixel" arithmetic for the title. A shared cells contract (label + state + action per cell, one measure pass, one index pass) would stop each multi-cell module growing its own.
- **clock is conceptually a *source*, not a *view*.** It is the only module that pushes (a deadline, a staleness bit) rather than pulls. Splitting a pure time source from a trivial text segment would make the segment side testable with a fake clock and reusable by any other time-dependent segment — the two halves are already separated (`deadlineFromMs`/`formatTime` vs. the `var`s), so this is an ownership question, not a rewrite.
- **Build modularity is already right; the leak is naming.** Each file binds exactly one `pub const module` in a build-enforced spelling and is independently deletable. The one wart: `layout/` is a *directory* with no package semantics, so the name implies an extensor relationship the build does not have.

**Grounding in code (step 3, second thoughts).**
- **Confirmed: width is a post-hoc report.** `drawAndStore` stores inside the draw body (segdraw.zig:96), the default `naturalWidth` returns that cache (segdraw.zig:183), and the bar measures *before* it draws (bar.zig:753-756, :1004). The concrete failure I confirmed: `tags` reserves 0 on the first pass, because `naturalWidthHook` returns `workspace_count * ws_width` (tags.zig:228) while `ws_width` stays 0 until `ensureCache` runs during the draw (tags.zig:64). The row under-reserves, `centerRowBudget` over-claims the center slot, and the 0-width `SegBound.contains` (bar.zig:410) makes tags unclickable that frame. Bounded to the first layout pass, since `ws_width` persists after.
- **Refuted: my "linear name→index scan" worry.** Neither file scans — `activeLayoutKind` returns the model's kind after a `moduleOf` bounds/null check (contract.zig:70-75) and the registry is indexed directly. My *other* claim held: the duplicated resolve-and-fallback is real (layout.zig:26-30 vs variants.zig:24-33), with two degradation vocabularies for one condition.
- **Second thoughts on `with_collapse = false` for layout: defensible today, latent, not a live bug.** segdraw.zig:28-34 justifies it with "layout.zig's width only changes on reload", but the icon changes on every click, and a click's redraw (`redrawInsideGrab` → `performDraw`, bar.zig:319, :1422-1426) measures before it draws — so a changed icon width is one pass behind with no re-lay requested. The saving grace: every in-tree layout passes a 3-glyph icon (`layoutModule("leaf", "BSP")`, `("master", "[]=")`, … tiling.zig:333), so the delta is a glyph or two in a proportional font. The invariant is accidental, not structural.
- **Second thoughts on the clock's failure throttle: the intent is documented but not implemented.** clock.zig:147-151 says the attempt is recorded *before* rendering so a persistent failure degrades to one retry per boundary. In fact `rendered_sec` is assigned at clock.zig:152, i.e. *after* the only failure point (`try formatTime`, clock.zig:137), and `updateClock` gates the repaint on `secondsElapsed` (bar.zig:1725), which stays true when the record is never written. So a failing `formatTime` retries once per event batch. The trigger is user-reachable: `clock_format` is unbounded config text (config/types.zig:511) and the format copy rejects ≥128 bytes (clock.zig:189).
- **Second thoughts on `keyedWidthState`: right idea, applied once — and `tags` is the one that needs it.** `ensureCache` caches *per-state* measurements (the selected cell may render bold, tags.zig:57-63) yet is keyed on nothing, invalidated only at bar creation/reload (tags.zig:43-45, bar.zig:602, :1305). After a workspace switch the newly-bolded cell is centred with a width measured in the unselected state. This is the section's strongest confirmed gap — and the clock's mode-keyed memo (clock.zig:140-146) is already the exact shape that fixes it.
- **Confirmed but smaller than expected: the model walk.** variants.zig:29-30 hand-indexes `m.ws[m.current.index].params.variant_idx` while `getCurrentLayout` does the same walk for `kind` (pipeline.zig:70-72) — a missing accessor, not a layering violation. Both files are otherwise pristine: their only edges are `contract`, `pipeline`, `actions`, `segdraw`, `drawing`, `types`.

Risk: low; behaviour-preserving if the two fallbacks are passed in. **Structural (small).**
7. **Decide what the `layout/` directory means.** Where: `src/bar/modules/layout/` vs the build's sub-registry spec list (build.zig:818-837 lists systatus/prompt/title/slider, *not* layout). ## 24. `src/bar/modules/title/` — title MODULE + carousel MODULE EXTENSOR
**Conceptual model (step 1).** Title is the bar's `center_slot` segment: the bar fills a per-frame `TitleSnapshot` (focused id/title, current-workspace window ids, per-window titles + truth-rects, minimized set) from in-process caches, and the module renders it either as one focused-window cell or as an equal-tiled split view, one cell per window. **Design brainstorm (step 2).**
- **Make the frame a value, not a query.** A per-frame `TitleLayout` (ordered cells, each carrying identity + resolved bounds) computed once and consumed by *both* draw and hit-test would make "what is under this pixel" a field read instead of a second derivation from the same snapshot.
- **Carousel as pure function of (identity, elapsed), not an accumulating ticker.** `offset(now) = mod((now − t₀)·speed/1000, cycle)` is idempotent per `now`: any two draws at the same timestamp produce the same pixel, so frame jitter, redundant draws, and event-loop reordering can never shift the text. - **Policy as data.** A `CarouselPolicy` value (gap, speed, direction, dwell-at-ends) would make "what the carousel does" one inspectable value, and would stop the wrap gap being a private constant while the speed is user config.
- **Separate motion from pacing.** The extensor should answer "how far along am I"; the bar/segment core should derive "when must I wake" from a declared period hint. Today the extensor owns *both*, which is why it must accept `hz` as a parameter and why the seam is five pointers wide. Splitting them would let the next animated thing (caret, progress) reuse one pacing path instead of reimplementing a ticker.
- **Inject pacing; don't import the global.** If `DrawCtx` carried a pacing budget, the module would never name `refresh`, and its draw would be idempotent.
- **Seam as capability query, not a fixed vtable.** Title asks "who decorates this overflowing cell?" and each addon contributes a strategy, rather than title hard-wiring index 0 of a homogeneous list. That permits click-to-pause, fade, or a second decorator.

## 25. `src/bar/modules/systatus/` — systatus MODULE + batt/cpu/ram MODULE EXTENSORS
**Conceptual model (step 1).** The systatus package is a closed-core/open-module readout belt that has been *decomposed*: there is no aggregate "systatus" segment any more, only a shared closed core (`systatus.zig`) plus one sibling per metric, each promoted to its own `contract.Segment` named after it. The core owns everything a readout shares — arm-on-first-draw, a 2 s poll deadline, change-diffing, and the two-color `<label> <pct>%` paint — while each extensor is a single `read() ?u8` function over a raw file. The data flow is: sysfs/proc file → `read()` → percent → `refresh()` renders one text buffer and remembers the byte range of the number → `drawPaddedSegmentValue` paints label and value in two colors while the drawn width is fed back as the row reservation.

**Design brainstorm (step 2).**
- **The seam is percentage-shaped, and that is the real design limit.** `Sub.read: *const fn () ?u8` means an extensor can only ever express "one 0-100 number". Net throughput, load average, temperature, disk usage, or a charging glyph + percentage cannot be expressed at all — the extensor must escape the package. A purer seam returns a typed `Sample` (value + optional state enum + optional raw), letting the core own the *one* place that turns a sample into text and into "which subslice is the value".
- **Unify width-track / mark-dirty / collapse.** The bar already owns a canonical implementation of "record painted width, re-lay the row when it changes" (`segdraw.widthState`). systatus reimplements the identical triple in parallel per-index arrays. Because every hook is comptime-indexed, the same helper could be instantiated per readout name and the two copies collapsed into one.
- **Who owns pacing?** A single *family* timer (one deadline for the whole registry, all readouts re-read in one sweep) is purer than N independent per-index timers, and matches the fact that every readout shares one cadence constant anyway. Relatedly, the bar polls the *whole* registry including unconfigured readouts; systatus survives that only because unarmed readouts report no deadline — correct, but implicit.
- **Three states, not one.** "Device absent" (no battery), "read failed transiently", and "metric unsupported by this kernel" are currently one value: `null`. The cleaner story separates them and makes *absence* sticky — a desktop with no battery should stop probing entirely, and a single transient failure must never delete a good reading.
- **Rendering should be one pure function returning offsets**, `render(sample) -> { text, value_start, value_len }`, instead of mutating three parallel arrays and handing the painter a subslice whose position it must re-derive by pointer arithmetic.
- **Backends should never own a draw function** (already true — they own only `read`), but the *state ownership* rule is implicit: a sampler like cpu keeps its own baseline across calls. That should be named in `Sub`, since a future rate-based extensor needs the same.

**Grounding in code (step 3, second thoughts).**
- **Confirmed, and better than I guessed — arm-on-first-draw is the load-bearing trick.** The bar takes the min deadline over *every* registry module (`src/bar/bar.zig:272`), not just configured ones, so an unconfigured readout is kept free solely because `pollDeadlineMsFor` returns `-1` while unarmed (`src/bar/modules/systatus/systatus.zig:128`). This is the right design and should not be touched.
- **Refuted: my "N timers de-phase" worry is nearly moot.** Every configured readout arms inside the same draw pass, so the family stays in phase; the only de-phase is a readout newly added by a config reload, costing one extra wakeup. A family timer is therefore *cleaner*, not *necessary* — I over-weighted this.
- **Confirmed gap — no sticky last-good, so a transient failure visibly blinks the segment out of the row.** `refresh` unconditionally overwrites `g_len[idx]` to 0 on any null read (`systatus.zig:105-119`), and `drawFor` then zeroes the slot width and re-marks dirty (`systatus.zig:158-164`): the readout vanishes and pops back.
- **Confirmed gap — no absent latch.** `batt.read` re-probes 8 sysfs paths every 2 s forever (`batt.zig:17-24`) on a machine that can never answer, and cannot distinguish "no battery" from "capacity file unreadable" (`batt.zig:22`).
- **Confirmed gap — the arm frame paints a fabricated number.** `drawFor` primes text at arm time (`systatus.zig:152`) and cpu's first read returns the *since-boot* average (`cpu.zig:38-50`), so a long-uptime machine shows e.g. "CPU 4%" for one frame, then jumps to live values 2 s later.
- **Refuted: reload staleness is a non-issue.** systatus binds no `invalidate`/`invalidateReloadCaches` (`systatus.zig:204-212`), but the bar is re-created and fully repainted on reload (`src/bar/bar.zig:1298-1304`) and the draw path re-measures and re-marks dirty (`systatus.zig:176-178`), so it self-corrects in one frame.
- **Bonus confirmed defect:** `dev/scripts/check-modularity.sh:281` still names the renamed `mem.zig`, and the script hard-errors on a missing scenario path (`check-modularity.sh:91-92`) — that gate is currently a guaranteed failure and `ram.zig` has no removal coverage.

**Final actionable improvements (step 4).**
1. **Quick win — fix the stale modularity scenario.** `dev/scripts/check-modularity.sh:281` names `src/bar/modules/systatus/mem.zig`; the file is `ram.zig`. *Why:* the script errors out on unknown paths (`:91-92`), so the "open-module churn" claim this package is built around is unverified. *Risk:* none.
2. **Structural (small) — sticky last-good.** In `refresh` (`systatus.zig:105-119`), keep the previous text on a null read and only collapse after N consecutive misses; let the collapse path (`systatus.zig:158-164`) fire solely from that. *Why:* removes a user-visible blink plus a spurious row re-lay on any single transient read error. *Risk:* low — needs a per-index miss counter.
3. **Structural refactor — widen the seam to a typed `Sample` + one pure `render`.** Replace `read: *const fn () ?u8` (`systatus.zig:51`) with a sample struct and make `refresh` (`systatus.zig:98-121`) a pure function returning `{ text, value_start, value_len }`. *Why:* unblocks non-percentage readouts and lets `drawPaddedSegmentValue` take explicit offsets instead of re-deriving them by pointer identity (`drawing.zig:797-813`). *Risk:* medium — touches the painter's signature; do it before a fourth readout lands.
4. **Structural (small) — make absence sticky and explicit.** Add an `absent` latch to the core so a never-answering sub stops being polled/probed (`batt.zig:17-24`), and give `Sub` a policy for "present but unreadable". *Why:* stops 8 futile sysfs opens every 2 s on desktops and makes the zero-width story deliberate rather than emergent. *Risk:* low.
5. **Structural (small) — don't paint the baseline reading.** Have cpu's first read return `null` (`cpu.zig:38-46`) so the arm frame collapses instead of showing a since-boot average. *Why:* removes a one-frame "CPU 4%" → "CPU 97%" jump caused by priming at `systatus.zig:152`. *Risk:* low; the slot is empty for one frame either way.
6. **Structural (small) — reuse the shared width tracker.** Replace `g_slot_width` + inline mark-dirty (`systatus.zig:73`, `systatus.zig:176-178`) with `segdraw.widthState`-style instances per readout name (`src/bar/segdraw.zig:17-40`). *Why:* the store/consume/naturalWidth triple already exists; a second copy invites drift. *Risk:* low, and all hooks are already comptime-indexed (`systatus.zig:186-203`).
7. **Structural (small) — split probe from parse.** Extract the sysfs/proc parsing (`batt.zig:22`, `cpu.zig:22-31`, `ram.zig:8-18`) into pure functions and test them, as `ram.zig:41-46` already does for `parseRamField`. *Why:* today only one parser is covered because it happened to be separable; a typed `Sample` makes all three testable without a filesystem. *Risk:* low.
8. **Quick win — cosmetic + robustness notes.** `batt.zig:30` labels "Batt" while its siblings use "CPU"/"RAM"; and `readSmallFile` (`systatus.zig:61-67`) silently truncates, so a meminfo exceeding the 4 KiB buffer (`ram.zig:23`) is indistinguishable from an absent field. *Why:* consistency, and a truncation that reads as "no RAM". *Risk:* none for the label, low for the buffer.

## 26. `src/bar/modules/slider/` — slider MODULE + brightness/volume MODULE EXTENSORS + native backends
**Conceptual model (step 1).** The slider is a closed-core MODULE: `slider.zig` owns everything a level-control shares — the per-segment lifecycle (arm on first draw, poll cadence, owed-commit sweep), the gesture shell (click = jump-to-position, press-hold = scrub, wheel = ±2%, right-click = secondary), the coalescing commit scheduler, and the label/drag-bar render. Each device is a MODULE EXTENSOR binding a `slider.Sub` (:260-299) that supplies only truth: presence, a 0-100 `pct`, `preview`/`commit`/`apply`, a display format, and a `secondary`. The value domain is a bare `u8` percent, and each native backend owns its own mapping into API space (sysfs `max_brightness`, ALSA `[min..max]`, PulseAudio `0..65536`).

**Design brainstorm (step 2).**
- **A `Level` value type instead of a bare `u8`.** One saturating constructor (`Level.of(pct)`, `Level.fromRaw(raw,min,max)`) makes the domain first-class: gesture math, render, and commit all speak the same type, and the "0-100 clamp is each control's single guard" contract becomes unrepresentable-to-violate rather than a documented invariant re-applied at each entry point.
- **Backend trait at a lossless divide.** The `Sub` surface should be `read() ?Level` / `write(Level)` / `describe() []const u8` — presence folded into the optional, native-unit mapping owned entirely by the backend. Today `has_value` + `pct` are two hooks for one fact, and the core carries a bare linear map it shares by convention.
- **Commit *cost* as data, not a question.** `commit_is_native() bool` makes the scheduler ask the backend to classify itself. A declarative `commit_cost: enum { immediate, rate_limited }` (or `throttle_ms: ?i64`) on `Sub` removes the policy question from the gesture path entirely.
- **One gesture reducer, not four entry points.** Click, motion, scroll and release are four independent hooks that each reach into the throttle. A single `Gesture { state: enum{idle,scrubbing}, anchor, last_target }` with a `feed(.{.press,.motion,.wheel,.release})` entry collapses the click-vs-drag distinction into "a scrub with zero motions" and makes the exclusive-drag invariant a type-state instead of a bare bool.
- **Value application separated from intent.** `preview`/`commit`/`apply` are three hooks all writing the same `g_pct` global plus a backend. A `Committer{ pending: ?Level, due_ms, policy }` owning intent, with the sub exposing only `read`/`write`, would delete the duplicated "clamp, write, maybe re-read" triplet in both extensors.
- **Geometry as a shared meter concept.** The drag range is the painted label width, and the `pct↔slot` map is a module-local pure helper. Any future meter (battery bar, CPU bar, network) re-derives it. A `bar/meter.zig` owning `{origin, length, pctFromPx, pxFromPct, fill fraction}` — with the *reserved* vs *painted* width distinction made explicit — is the honest home.
- **Render as one pure function of `(Level, mode, geometry, format)`.** `drawDragBar` and the `drawPaddedSegmentValue` label path are two paint programs with different color sources; one input record would make the two-color numeric split and the fill fraction share the same padded-box math.

## 27. `src/bar/modules/prompt/` — prompt MODULE + vim MODULE EXTENSOR
**Conceptual model (step 1).** The prompt is a bar overlay that owns the whole title slot and grabs the keyboard while open, wrapping three concerns in one module: a byte-buffer line editor (`EditorState{buf,len,cursor,mode}`, prompt.zig:53-79), a completion engine that ghost-suggests from a fixed `$PATH` executable table plus a shell-history ring, and a full frame renderer (pill, caret, scroll, ghost text) that caches Pango measurements. The vim engine is a MODULE EXTENSOR that swaps prompt's `Handlers` function-pointer table (prompt.zig:208-224) for modal editing, layered *on top of* — not inside — the base readline state machine, gated at runtime by `config.bar.vim_mode`.

**Design brainstorm (step 2).**
- **A real text-buffer type, not four fields.** The buffer should own its invariants: `insert`/`deleteRange`/`overwrite`/`moveCursor` as the only mutators, with cursor clamping and length invariants inside. Today the extensor reaches into `vs.buf`/`vs.len` directly, so the "contract" is raw field access.
- **Split key decoding from edit semantics into a value type.** Decode once (X event → `Key{sym, ctrl, shift}`), then map through a per-mode table → `EditOp`/text. Today the "key" the editor sees is a raw keysym with ctrl smuggled in as a separate dispatcher branch, and the X-specific 0x20–0x7e printable range leaks into the buffer layer.
- **Completion as a candidate source, not a command-string heuristic.** A `CompletionSource` seam (history entries, `$PATH`, later: desktop files, arg specs) queried by a `wordAtCursor` token, instead of one function that special-cases the first token and bails on any space.
- **The runtime mode switch should be "no addon active", not "vim off".** A capability/active-flag owned by the addon seam, so config toggles a uniform thing and future addons aren't special-cased.
- **Hint/command rendering policy belongs in the mode provider.** The right-pinned pill, its label, and its reserved width are rendering policy leaking into the host; the host should only reserve `hintWidth()`.
- **Vim should interlock as a *mode* on the base machine**, owning pending-operator state and translating motions into base `EditOp`s, rather than shadowing `handle_insert`/`handle_ctrl`.

**Grounding in code (step 3, second thoughts).**
- **Confirmed: the buffer is a real edit model, and it's genuinely good.** `EditorState` separates storage from rendering, `reset` preserves the allocation (prompt.zig:68-73), and `insertSlice` is a correct bounded mid-string insert with `copyBackwards` (prompt.zig:82-96). Rendering never mutates. I over-predicted a "rendered string" anti-pattern — it isn't here.
- **Confirmed gap: the buffer API is one method wide.** `insertSlice` is the sole `pub` mutator; the four private helpers each re-roll the same memmove with their own cursor policy (prompt.zig:105-152, 180-206), and vim re-implements a *fifth* with different normal-mode clamping (vim.zig:270-278) plus a raw in-place byte write for `~` (vim.zig:313-318). Five copies of `copyForwards` + len/cursor bookkeeping.
- **Confirmed: decoding and semantics are already half-separated, and the seam leaks.** `handleKeyPress` (prompt.zig:492-548) does decode/route; handlers take `(es, sym)`. But ctrl is a dispatcher branch (prompt.zig:521-527), not part of the key value, and `isPrintableAscii` hardcodes an X keysym range into the editor (prompt.zig:98-100) — so no non-ASCII byte can ever be typed. That's the confirmed limit, not a misjudgement.
- **Refuted (I was wrong): the mode switch isn't tangled.** `vimModeEnabled()` is just `config.bar.vim_mode` (prompt.zig:357-359) — no addon-side state to unwind. The real smell is narrower and worse: it's read in three places (prompt.zig:510, 646, 1203) and the off-switch hardcodes a bypass of *one* handler for *one* mode (prompt.zig:538-539), so a second addon would be silently ignored in insert mode.
- **Confirmed gap: completion is a first-token guesser.** `updateGhost` requires cursor-at-end and no space anywhere (prompt.zig:756), then scans all 128 history entries doing a binary search per entry (prompt.zig:764-773) — and discards a history match whose command isn't an exact `$PATH` table hit. The token concept exists (first-space split) but is never generalized.
- **Also confirmed: derived state by heuristic.** `has_space` is recomputed only when `len` changes (prompt.zig:552-554) — sound today only because no edit changes space-ness at constant length, and `activate` must remember to reset it separately (prompt.zig:603). Cache invalidation is likewise a hand-maintained list (prompt.zig:344-355).
- **Bonus finding: the names lie.** The whole surface is `drun_*` (config keys at types.zig:537-540) with a `"run: "` default prefix (types.zig:403) and a `.local/share/drun/history` path (prompt.zig:42), but nothing parses `.desktop` files — it's a `/bin/sh -c` runner over `$PATH` (prompt.zig:947-974). Also `drawActive` copies the entire `types.BarConfig` by value every frame (prompt.zig:1292-1296). Only the pure editor/vim state machine is tested (`src/test/bar/vim_test.zig`); completion, history, and rendering are untested.

**Final actionable improvements (step 4).**
1. **Widen the `EditorState` mutator API** — add `deleteRange(from,to)` and `overwriteAt(pos,bytes)` next to `insertSlice` (prompt.zig:82-96), then delete vim's `deleteRange` (vim.zig:270-278) and `toggleCaseOnce` (vim.zig:313-318). *Why:* five divergent memmove+clamp copies; the extensor's edits are the least-tested. *Risk:* low — normal-mode clamp moves into the buffer, needs a mode-aware delete. **Quick win.**
2. **Make `has_space` a function of the buffer, not cached state** — drop the field and the length-delta heuristic (prompt.zig:300, 552-554) and test `indexOfScalar` at the single consumption point (prompt.zig:756); it is O(256) on a buffer already scanned per key. *Why:* removes a hand-maintained invariant spanning two reset sites. *Risk:* none. **Quick win.**
3. **Generalize completion to a token-aware source seam** — lift the first-space split already at prompt.zig:764 into a `wordAtCursor` helper and drive candidate lookup from a small `CompletionSource` union (history ring vs. sorted exe table), removing the `has_space` bail. *Why:* the current shape can't complete an argument, and the per-entry binary search (prompt.zig:766) is the hot path. *Risk:* medium — behavior change users may notice (more ghosts). **Structural (small).**
4. **Replace the hardcoded insert-mode bypass with an addon-active flag** — have `registerHandlers` also set `addon_active = true` (prompt.zig:226-228) and branch on that at prompt.zig:538-539 and 1203, so `bar.vim_mode` becomes a *policy* input the addon consults rather than a second dispatch mode. *Why:* today a future addon is bypassed in insert mode and its pill width is suppressed. *Risk:* low-medium — changes what "vim off" means for a compiled-in vim. **Structural (small).**
5. **Give `Mode` a first-class hint width instead of reaching through the handler table in `drawPill`** — the host currently calls `handlers.mode_label` (prompt.zig:48-50) and caches its width per mode (prompt.zig:286, 1203-1206), so the *host* renders the *extensor's* UI policy. Move the pill into the mode provider or expose `Mode.hintWidth`. *Why:* keeps `BarOverlay.draw` a host concern. *Risk:* medium — touches the one region a mode-label change must re-cache. **Structural (small).**
6. **Take `config` by pointer in `drawActive`** — prompt.zig:1292-1296, threaded from `draw(ctx)` (prompt.zig:577). *Why:* a full `BarConfig` struct copy per frame for reads only. *Risk:* very low. **Quick win.**
7. **Rename the `drun_*` surface to match the model** — config keys, `default_drun_prompt` (types.zig:403), `drunBg/drunFg/drunPromptColor` (types.zig:582-589), and `drun_history_suffix` (prompt.zig:42) describe a desktop-file launcher; the code is a `$PATH` shell runner. *Why:* the naming is the largest conceptual lie in the section and misleads every reader. *Risk:* medium — user-facing config keys need an alias. **Structural refactor.**

## 28. `src/test/` — test organization, helpers, fixtures
**Conceptual model (step 1).** `src/test/` is a test-only subtree, auto-discovered by `build.zig` and run as ~34 independent test roots, each in its own process with the production named-import graph cross-wired (so `zig test <file>` cannot resolve them). It is organized as a *semantic* mirror of `src/` (`core/`, `config/`, `engine/`, `window/`, `bar/`, `input/`, plus a test-only `latency/`), with three layers stacked on top of that: (a) headless pure/state-machine tests driven by free-function helpers in `helpers.zig`, whose centerpiece is `TestSink` — a comptime-parameterized fake of the `sink.Sink` send seam in four modes (count/category/record/none); (b) X-gated integration tests that boot the *real* `core → window → pipeline` wiring over a live Xvfb through `window/fixture.zig`; (c) a build-side gate table that binds every `*_test` file to a feature gate and an `x_gated` serialization flag, failing the build on any missing or stale row. Determinism is bought with three devices: re-armed process-global module stores, golden rects derived from shared constants, and an env-var-controlled skip (`HANA_REQUIRE_X`) that turns silent self-passes into panics.

**Design brainstorm (step 2).**
- **Layout by *layer*, not by path.** Path mirroring has already leaked: `engine/` has no `src/engine/`, `model_test.zig` lives under `engine/`, and the same production file is split across two files by X-ness (`borders_pure_test` / `borders_test`). A three-bucket layout — `contract/` (does a module satisfy its declared seam), `mechanism/` (pure state machines, no X), `integration/` (real server), `bench/` — would make the "meaning vs mechanism" distinction structural instead of a naming convention a reader must infer.
- **A fixture object, not global-mutating free functions.** `testReset()` reaches into other modules' process-global stores; that is a convention every test must remember. A `Fixture{ model, sink, ledger, alloc }` value passed by pointer, with reset-in-`init`, makes ordering independence a type-level property instead of a doc-comment, and lets the allocator be per-test.
- **The sink should be a *port*, not just a recorder.** `Sink.VTable` returns `void` everywhere, so no fake can fail, block, or observe a flush/grab boundary. A `.fail_at(n)` mode plus recorded `flush`/`grab_server`/`ungrab_and_flush` ops would let write-path tests assert the failure protocol, and would let reconcile's "grab, mutate, ungrab+flush" batching become an assertion rather than a comment.
- **One temp-dir strategy.** The hand-rolled PRNG `/tmp/.hana-test-<tag>` dir duplicates a capability `std.testing.tmpDir` already provides, and its cleanup logic can orphan a directory and litter `/tmp`. A single `tmpDir`-based helper (leak-checked, self-cleaning) removes a whole module.
- **Skip must be a runner-visible outcome.** Zig already has `error.SkipZigTest`; the X path instead returns a bare `pass`, so a green run with six files silently skipped is indistinguishable from a green run that executed them. Express skip uniformly and let `HANA_REQUIRE_X` be the *policy* rather than the *mechanism*.
- **The gate table is a second source of truth.** Every test file already encodes its own feature dependency via `build_options.has_*`; the build re-states it as a 34-row table. Let the test file declare its own requirement (or skip itself) and keep the table for `x_gated` only.
- **Benchmarks need a home that can print.** Bench output goes to stderr, which the build runner reports as a failed command; a `zig build bench` step writing to a file (or a custom `std.Build.Step`) separates measurement from the pass/fail contract.

**Grounding in code (step 3, second thoughts).**
- **Confirmed, and stronger than I guessed: the shared vocabulary is mostly unused.** Only 10 of 34 test files import `helpers` (all of `bar/`, `config/`, `input/`, `core/`, and `window/actions|focus|borders` hand-roll their own setup). The deep-dive's "the module most of the suite imports" is refuted — it is the vocabulary of the engine+latency cluster only.
- **The two entry points into helpers diverge dangerously.** `setUpModel()` (helpers.zig:38) resets the minimize/fullscreen stores; `makeModel()` (helpers.zig:13) does not. `model_test.zig:51` aliases the safe one, but `workspaces_test.zig:19` and `borders_pure_test.zig:15` call the unsafe one — and `floating` has a process-global `g_state` (`src/window/modules/floating.zig:125`) that `testReset` never resets (helpers.zig:23-32) even though `model_test.zig` drives `floating.honorConfigureRequest`. Order-dependence is a live, not theoretical, hazard.
- **Confirmed gap: five of eleven vtable entries are unobservable.** `TestSink` no-ops `set_ewmh_fullscreen`, `flush`, `grab_server`, `ungrab_and_flush` (helpers.zig:227-230), yet production calls `setEwmhFullscreen` from `fullscreen.zig:195`. `stack_only` *is* recorded (helpers.zig:220-225) but there is no `expectStack` anywhere in `src/`, so the assertion set covers 7 of 8 recorded op kinds. The fullscreen→minimize→restore gate in `reconcile_test.zig` therefore proves geometry, not the EWMH state list.
- **Confirmed: `-Dbench` cannot go green.** Every bench print is `std.debug.print` (e.g. `perf_test.zig:64`, `tiling_latency_test.zig:67`) — stderr, which build.zig:54 itself names as the thing the runner flags as `failed command:` "even on success". The documented opt-in path (README:259-260) is red by construction.
- **Confirmed and worse than expected: X-need is a property of the fixture, not the assertion.** `borders_test.zig:1-7` documents its subjects as "the pure public reads" (`core.borderWidth()`, `borders.resolveBorderColor()`), yet build.zig:280 marks it `x_gated = true` and every test opens the fixture (`borders_test.zig:24,46,71`) — so a headless CI silently skips three pure-function tests. Meanwhile `engine/tiling_test.zig:274,432` uses `error.SkipZigTest` properly, so the tree carries two different skip idioms.
- **Mildly misjudged: the "no fake XCB wire layer" is a real cost, not a neutral choice.** Because there is no wire recorder, the extracted production half of the seam — `XcbSink.setEwmhFullscreenShim`'s client-atom preservation and `bytes_after` bail (`sink.zig:184-230`), and `requests.configureWindow`'s merge — has no test at all; the seam was made substitutable for tests, and the substitutable half is untested. Also confirmed: the runner exposes no filter and no per-file step (all 34 runs hang off one `unit_test_step`), and the `x_gated` chain order derives from `StringHashMap` iteration, so serialization order is unspecified.

**Final actionable improvements (step 4).**
1. **Record the five silent sink ops and add the missing assertion** — `helpers.zig:227-230`: turn `setEwmhFullscreen`/`flush`/`grab_server`/`ungrab_and_flush` into recorded ops and add `expectStack` beside `expectPark`. *Why:* 4/11 vtable entries and 1/8 op kinds are currently unassertable, so the fullscreen EWMH transition (`fullscreen.zig:195`) has no headless test. *Risk:* low — additive; existing `expectLen` counts in `reconcile_test.zig` change, so those baselines need re-baselining. *Quick win.*
2. **Make `-Dbench` exit green** — `perf_test.zig:64` (and the seven other `debug.print` sites): either write timings to a file under `.zig-cache`/`zig-out`, or add a `zig build bench` step that runs the same artifacts outside the test protocol. *Why:* build.zig:54 documents the stderr rule the bench mode violates; today the documented path reports failure. *Risk:* low. *Quick win.*
3. **Collapse `makeModel`/`setUpModel` into one reset-by-default fixture, and extend the reset to `floating`** — `helpers.zig:13-41`; callers `workspaces_test.zig:19`, `borders_pure_test.zig:15`, `model_test.zig:51`. *Why:* two entry points with different guarantees, and `floating.g_state` (`floating.zig:125`) is never re-armed despite `model_test` driving it. *Risk:* low (rename + add one `deinit/init` pair). *Quick win.*
4. **Give every X-gated test a real `error.SkipZigTest` and split `borders_test`** — `fixture.zig:72-94`, `borders_test.zig:24,46,71`. *Why:* today a skip is a silent pass; Zig's skip is reported as SKIP by the runner, and `HANA_REQUIRE_X` can then be expressed as "skip becomes `error.SkipZigTest` → `unreachable`" instead of a duplicated panic branch. Pure `borderWidth`/`resolveBorderColor` assertions belong headless next to `borders_pure_test.zig`. *Risk:* medium — touches 5 files and the skip banner UX. *Structural (small).*
5. **Delete `config/scratch.zig` in favour of `std.testing.tmpDir`** — `scratch.zig:14-53`; reference the pattern already used at `brightness_test.zig:20`. *Why:* two competing temp strategies, a PRNG-from-clock uniqueness argument where Zig already guarantees isolation, `page_allocator` paths outside leak checking, and a cleanup that nulls `scratch_dir` even when `deleteDirAbsolute` fails (scratch.zig:51-52), orphaning a non-empty dir. *Risk:* medium — `config_test.zig:20`, `schema_test.zig:31`, `persist_test.zig:64` all take absolute path strings; persist/config APIs may need `tmpDir.realPath`. *Structural (small).*
6. **Let test files declare their own gate; shrink `test_gates` to `x_gated`** — `build.zig:250-285` vs. each file's `build_options.has_*` checks. *Why:* 34 rows of duplicated truth that must agree with the sources; the staleness guards (build.zig:296-323) then protect a table that is one boolean. *Risk:* medium-high — touches the build's central safety net. *Structural refactor.*
7. **Move the runner onto a sorted, filterable step list** — `build.zig:288-336`: iterate a sorted stem list instead of the discovery map iterator and name each run step (`<file>`), plus forward args as a `--test-filter`. *Why:* unspecified `x_gated` chain order and no way to run one file during development. *Risk:* low, mechanical. *Quick win.*
8. **Retire test-owned oracles in favor of production seams** — `slider_test.zig:12-25` re-implements the slot hit-test; `fixture.zig:380-416` re-derives the engine's placement; `perf_test.zig:161` hardcodes `100` instead of `helpers.focused_pixel`. *Why:* duplicated logic rots silently and disagrees with the code it checks; `expectedPlacementOf` is the worst case because it can only ever confirm the engine agrees with itself. *Risk:* medium — the fixture oracle is currently load-bearing for the X-gated tile assertions. *Structural refactor.*
